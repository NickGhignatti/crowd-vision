How the services talk, and why each talk looks the way it does.

Pick by what happens if the message is lost

StyleUsed forIf lost
HTTP with claimsA person is waitingThe person sees an error
HTTP with HMACNo person involved, like provisioningRetried on the next round
Redis pub/subLive readings, in-app alertsNothing: the next tick replaces it
KafkaBreaches, building registration, Wi-Fi ticksNot lost, read after a restart

Example. dashboard restarts for 10 seconds. Readings of those 10 seconds never reach its channel. Fine: a new tick comes, and a client that reconnects asks telemetry for the latest values. A breach in those 10 seconds waits in Kafka, because nothing else would remember it.

Two services never share a group

A group shares the work: each partition goes to one member. These topics have one partition, so in a shared group one service would read everything and the other nothing. Copies of one service do share a group.

Renaming a group replays the topic

No saved position means reading from the start. Harmless for registration, since every write is an upsert. For alerts, old breaches go out again as real pushes, limited only by the cooldown. Wait for retention to pass, or move the new group to latest first.

Flows

A reading reaches the screen

  • One bad reading refuses the whole batch. At most 500 readings.
  • 202 means stored, so the data can be queried.
  • dashboard and socket pass the bytes on, unread. Columns are applied in the browser, so the 3D twin still gets every metric.

A breach reaches a person

  • Same message, two roads: bell in the app, push outside it.
  • The push road needs no open tab.
  • Delivery can happen twice, so a Redis cooldown of 300 s absorbs repeats.
  • Failed lookup: parked on alerts.dlq, cooldown not set.
  • No owner: dropped, and counted.

A building is registered

  • Validation runs before the answer, so a bad file is refused at once.
  • Each side commits only after handling, and every write is an upsert. Repeats change nothing.
  • resync sends the request again when telemetry lost a building.

Wi-Fi ticks

Bytes go on as received, and unknown fields are refused, so a stray MAC address cannot reach Kafka. Details: Wireless People Flow.

Sign-in

Later requests need no call to tenancy. The app renews every 10 minutes.

Signup

A 409 from tenancy counts as success, so a repeat is safe.

A question to the assistant

The same access rules apply as if the person had called directly. The assistant holds no rights of its own.
