telemetry is a Rust service (Axum, PostgreSQL with TimescaleDB, Kafka, Redis) in backend/telemetry. For the role and the choices behind it, read Telemetry architecture. For storage, Telemetry Storage.

It is the door for every sensor reading. It checks, stores and hands on readings. It also owns the limits, the sensors and the device commands, and it raises an alert for every breach.

The idea in one minute

Imagine the mail room of a big building.

  • Sensors drop off parcels (readings). A parcel must have the right label: which building, which room, which kind of sensor, and a value. A parcel with a wrong label is refused, and so is the whole batch it came in.
  • At the door, a guard checks the seal (the signature). Only a device that knows the building’s key can make a valid seal.
  • Accepted parcels go in three places at once: into the archive (PostgreSQL), onto the live belt for the dashboards (Redis), and, if a value is past its limit, a red slip goes to the alarm office (the alerts topic on Kafka).
  • Each kind of sensor is a plugin: one small file that says “I am temperature, my value is in this field, my limits are maxTemp and minTemp”. The mail room itself does not know what a temperature is. Adding a new kind of sensor means adding one file.

Plugins: one file per kind of sensor

A plugin has to answer five questions. They are the SensorPlugin trait in types/plugin.rs:

pub trait SensorPlugin: Send + Sync {
    fn key(&self) -> &'static str;
    fn descriptor(&self) -> &MetricDescriptor;
    fn validate(&self, payload: &Value) -> Result<Reading, Vec<String>>;
    fn bounds(&self) -> &'static [BoundSpec];

    fn actions(&self) -> &'static [ActionSpec] {
        &[]
    }
}
  • key: its name (temperature). This is the type a reading carries.
  • descriptor: label, unit, and the list of fields a reading must have.
  • validate: turn raw JSON into a checked Reading, or a list of complaints.
  • bounds: which limits it has.
  • actions: which commands a device can get (default: none).

The field specs

pub enum FieldKind {
    NonEmptyString,
    Finite,
    NonNegativeInt,
}

pub struct FieldSpec {

    pub kind: FieldKind,
    pub required: bool,

fn accepts(kind: FieldKind, value: &Value) -> bool {
    match kind {
        FieldKind::NonEmptyString => value.as_str().is_some_and(|s| !s.is_empty()),
        FieldKind::Finite => value.as_f64().is_some(),
        FieldKind::NonNegativeInt => value.as_f64().is_some_and(|n| n >= 0.0 && n.fract() == 0.0),
    }
}

A field is a name, a kind and “required or not”. check_fields runs every spec and collects messages like temperature: must be a finite number. A missing optional field (or null) is fine.

Two limits. key is the name of the limit in the stored bounds (maxTemp). field is the payload field it is compared with. direction says “breach when above” or “breach when below”.

fn validate(&self, payload: &Value) -> Result<Reading, Vec<String>> {
    let errors = check_fields(DESCRIPTOR.fields, payload);
    if !errors.is_empty() {
        return Err(errors);
    }
    let value = payload[DESCRIPTOR.value_field].as_f64().unwrap_or_default();
    Ok(reading(payload, DESCRIPTOR.key, value))
}

validate is short: check the fields, and if there are no complaints, read the value and build the Reading. The actions are setTarget(target), increase(step?) and decrease(step?).

The seal on a batch: ingest_auth.rs

Devices do not have a person’s JWT. They sign each request instead.

A key, and how to sign

pub fn sign(&self, body: &[u8]) -> String {
    let mut mac = Hmac::<Sha256>::new_from_slice(&self.0).expect("hmac accepts keys of any length");
    mac.update(body);
    mac.finalize().into_bytes().iter().fold(String::new(), |mut hex, byte| {
        let _ = write!(hex, "{byte:02x}");
        hex
    })
}

HMAC-SHA256 over the body bytes, written as lowercase hex. A key shorter than 32 bytes is refused when it is made (IngestKey::new), so a weak secret fails at start.

One key per building, never stored

/// The building's key at `epoch`: hex HMAC(master, "{building}:{epoch}").
pub fn derive(&self, building_id: &str, epoch: i32) -> String {
    self.master.sign(format!("{building_id}:{epoch}").as_bytes())
}

pub async fn issue(&self, building_id: &str) -> anyhow::Result<Option<String>> {
    let epoch = self.epochs.rotate(building_id).await?;
    Ok(epoch.map(|epoch| self.derive(building_id, epoch)))
}

There is one master key (TELEMETRY_DEVICE_MASTER_KEY). A building’s key is the HMAC of the master key over "{buildingId}:{epoch}". So:

  • No device key is ever stored. The only stored state is the building’s device_key_epoch number.
  • To revoke a key, bump the epoch (issue). The old key stops working at once, and the new key is shown once.
  • A leaked key of building b1 does not open b2: the epoch string is different.

Example. b1 at epoch 2. Rotation sets epoch 3. A collector still signing with the epoch 2 key gets 401 until it is given the new key. b2 is not affected.

Who is accepted

pub async fn accepts(&self, building_id: Option<&str>, message: &[u8], signature: &str) -> bool {
    let signed_by = |key: &IngestKey| constant_time_eq(&key.sign(message), signature);
    if self.shared.as_ref().is_some_and(signed_by) {
        return true;
    }
    let Some(building_id) = building_id else { return false; };
    match self.epochs.epoch(building_id).await {
        Ok(Some(epoch)) => IngestKey::new(&self.derive(building_id, epoch)).is_ok_and(|key| signed_by(&key)),
        Ok(None) => false,
        Err(error) => { log::warn!("device key epoch unreadable for {building_id}: {error:?}"); false }
    }
}
  1. The optional shared key (TELEMETRY_INGEST_SECRET) signs for any building. It is for local runs and simulators only.
  2. Otherwise, work out the building’s key from its current epoch, and compare.
  3. Unknown building, or an epoch that cannot be read: not accepted.

The epoch is read from PostgreSQL on every request, never cached, so a rotated key stops working on every copy of the service at once.

fn constant_time_eq(a: &str, b: &str) -> bool {
    a.len() == b.len()
        && a.bytes().zip(b.bytes()).fold(0u8, |acc, (x, y)| acc | (x ^ y)) == 0
}

The comparison looks at every byte and never stops early, so the time it takes does not reveal how many leading characters of a guess were right.

The middleware for a batch

pub async fn verify_signature(State(keys): State<DeviceKeys>, request: Request, next: Next) -> Result<Response, StatusCode> {
    let Some(signature) = request.headers().get(SIGNATURE_HEADER).and_then(|v| v.to_str().ok()).map(str::to_owned)
    else {
        metrics::record_ingest("unknown", "unsigned");
        return Err(StatusCode::UNAUTHORIZED);
    };

    let (parts, body) = request.into_parts();
    let bytes = axum::body::to_bytes(body, MAX_BODY_BYTES).await.map_err(|_| StatusCode::PAYLOAD_TOO_LARGE)?;

    // Read only to pick the key; the handler still validates the whole body.
    let building = serde_json::from_slice::<Addressed>(&bytes).ok();
    let building_id = building.as_ref().map(|b| b.building_id.as_str());
    if !keys.accepts(building_id, &bytes, &signature).await {
        metrics::record_ingest("unknown", "bad_signature");
        return Err(StatusCode::UNAUTHORIZED);
    }

    Ok(next.run(Request::from_parts(parts, Body::from(bytes))).await)
}
  1. No x-signature: 401, counted unsigned.
  2. Read the body, at most 1 MiB (1 << 20). More: 413.
  3. Peek at buildingId only to choose the key. The real handler still validates the whole body.
  4. Wrong seal: 401, counted bad_signature.
  5. Put the very same bytes back and let the request through.
  • The signature is over the exact bytes sent. A body formatted again by a proxy fails.
  • The same golden vectors (schemas/fixtures/internal-signature.json) are checked by the Go services, so the scheme cannot drift on one side.

The collector’s GET

A GET has no body, so the collector signs a made-up message instead:

pub fn collector_message(building_id: Option<&str>, timestamp: &str) -> String {
    format!("GET /collector\n{}\n{timestamp}", building_id.unwrap_or_default())
}

pub fn is_fresh(timestamp: &str, now_s: i64) -> bool {
    timestamp.parse::<i64>().is_ok_and(|stamped| (now_s - stamped).abs() <= MAX_SKEW_S)   // 300
}

The signed text is GET /collector, the building, and the time (x-timestamp). verify_collector_request accepts only a signature that is valid and fresh (within 300 s of the server’s clock). A captured request is useless after 5 minutes.

Without buildingId only the shared key passes, and it reads every building.

Each router in the answer has sensorId, roomId, and driver, endpoint only when set. Never a login.

Ingesting a batch: kernel/ingest.rs

This is the heart of the service.

pub const MAX_BATCH_READINGS: usize = 500;

pub struct Ingest {
    pub registry: Arc<PluginRegistry>,

    pub thresholds: Arc<dyn ThresholdStore>,

Seven collaborators. Six are ports. registry is the list of plugins. The clock is a port so tests can fix the time.

Step 1: check everything first

pub async fn accept(&self, building_id: &str, items: &[Value]) -> Result<usize, DomainError> {
    if items.len() > MAX_BATCH_READINGS {
        return Err(DomainError::Validation(format!("readings: must not exceed {MAX_BATCH_READINGS} per batch.")));
    }

    let mut errors = Vec::new();
    if building_id.trim().is_empty() {
        errors.push("buildingId: must be a non-empty string.".to_owned());
    }
    if items.is_empty() {
        errors.push("readings: must not be empty.".to_owned());
    }

    let mut readings = Vec::with_capacity(items.len());
    for (index, item) in items.iter().enumerate() {
        match self.reading_from(building_id, item) {
            Ok(reading) => readings.push(reading),
            Err(message) => errors.push(format!("readings[{index}]: {message}")),
        }
    }
    if !errors.is_empty() {
        return Err(DomainError::Validation(errors.join(" ")));
    }
  • More than 500 readings: refused before any work.
  • An empty batch or a blank building: complaints.
  • Then every reading is checked, and all the complaints are collected, joined, and returned as one 400. Nothing is stored, nothing is published. A batch is all or nothing.

Step 2: store and look up the limits at the same time

let keys: Vec<(&str, &str)> = readings.iter().map(|r| (r.metric.as_str(), r.room_id.as_str())).collect();
let (inserted, resolved) = tokio::join!(
    self.readings.insert(&readings),
    self.thresholds.resolve(building_id, &keys),

inserted?;

    log::error!("threshold evaluation failed: {error}");
    Vec::new()
});

tokio::join! runs the insert and the limit lookup at the same time. The insert is one statement with on conflict do nothing. The two outcomes are treated differently:

  • The insert fails (inserted?): the whole call fails with 500. Nothing is published and no alert goes out.
  • The limit lookup fails: it is logged (threshold evaluation failed) and treated as “no limits”. The readings are stored and published, but there are no alerts for that batch.

Step 3: breaches

for (reading, bounds) in readings.iter().zip(resolved) {
    self.raise_breach(reading, bounds).await;
}

For each reading, resolved holds its limits (or nothing). resolve picks the room’s bounds when it has any, else the building’s. Room bounds replace building bounds; they are not merged.

pub fn breaches(spec: &[BoundSpec], bounds: &Bounds, payload: &Map<String, Value>) -> Vec<Breach> {
    let mut found: Vec<Breach> = Vec::new();
    for bound in spec {
        if found.iter().any(|seen| seen.bound.field == bound.field) {
            continue;
        }
        let threshold = bounds.get(bound.key).and_then(Value::as_f64);
        let value = payload.get(bound.field).and_then(Value::as_f64);
        let (Some(threshold), Some(value)) = (threshold, value) else { continue; };
        let breached = match bound.direction {
            BoundDirection::Above => value > threshold,
            BoundDirection::Below => value < threshold,
        };
        if breached {
            found.push(Breach { bound: *bound, value, threshold });
        }
    }
    found
}

For each limit the plugin declares, in order:

  • This field already breached? Skip. One alert per field, and the first listed limit wins.
  • The limit value or the payload value is missing? Skip.
  • Above: breach when value is greater than the limit. Below: breach when it is smaller.

A limit compares its own payload field, not the reading’s main value. That is why air quality can limit co2 and indoor_aqi separately.

Wi-Fi ticks: kernel/observations.rs

ap-collector polls the routers about every 10 seconds and sends one snapshot per building.

pub async fn accept(&self, body: &[u8]) -> Result<(), DomainError> {
    let tick: WifiObservations = serde_json::from_slice(body)
        .map_err(|error| DomainError::Validation(format!("wifi observations: {error}.")))?;
    let problems = tick.problems();
    if !problems.is_empty() {
        return Err(DomainError::Validation(problems.join(" ")));
    }
    let sensors = self.sensors.by_building(&tick.building_id).await?;
    let readings = room_readings(&tick, &sensors);
    if !readings.is_empty() {
        self.ingest.accept(&tick.building_id, &readings).await?;
    }
    Ok(self.events.publish_observations(&tick.building_id, body).await?)
}
  1. Parse the tick. Unknown fields are refused: the bytes travel on to Kafka as received, and a stray mac field would travel with them.
  2. problems() (from the shared crate) checks the tick against the contract. Any problem: 400, nothing published.
  3. Load the building’s sensors and turn the tick into counts per room.
  4. Store those counts through the normal Ingest path.
  5. Publish the received bytes (never a re-serialised copy) to wifi-observations, keyed by the building.

Counting phones per room

fn room_readings(tick: &WifiObservations, sensors: &[Sensor]) -> Vec<Value> {
    let rooms: HashMap<&str, &str> = sensors.iter()
        .filter(|sensor| sensor.sensor_type == ROUTER)
        .filter_map(|sensor| Some((sensor.sensor_id.as_str(), sensor.room_id.as_deref()?)))
        .collect();

    let mut loudest: HashMap<&str, (i32, &str)> = HashMap::new();
    for phone in &tick.connected {
        let Some(&room) = rooms.get(phone.router.as_str()) else { continue; };
        let heard = (phone.signal, room);
        loudest.entry(phone.token.as_str())
            .and_modify(|best| *best = (*best).max(heard))
            .or_insert(heard);
    }

    let mut counts: BTreeMap<&str, u64> = tick.answered.iter()
        .filter_map(|router| Some((*rooms.get(router.as_str())?, 0)))
        .collect();
    for (_, room) in loudest.into_values() {
        *counts.entry(room).or_default() += 1;
    }
    // … one totalDeviceCount reading per room; ratioDeviceCount too when devicesPerPerson is set
}
  1. Map each router that sits in a room: router id to room id. Outdoor routers and other sensors are left out.
  2. For each connected phone on a mapped router, keep its loudest hearing: the largest (signal, room) pair. On equal signal the room id that sorts last wins.
  3. Start every room whose router answered at 0.
  4. Add 1 to the room of each phone’s loudest hearing. A phone counts once.
  5. One totalDeviceCount reading per room, stamped with the tick time.
  6. When the tick has devicesPerPerson, also ratioDeviceCount = count ÷ factor, rounded up. The source says why: rounding down 0.4 of a person would report an occupied room as empty.

Example. Routers r1 in lobby, r2 in hall. Both answered. Factor 2.5.

PhoneHeard byCounts in

Readings: totalDeviceCount lobby 2, hall 1. ratioDeviceCount lobby ⌈2 ÷ 2.5⌉ = 1, hall ⌈1 ÷ 2.5⌉ = 1.

Each room becomes an estimatedOccupancy reading and goes through the same Ingest, in chunks of 500. It is never added to totalDeviceCount: the two place a phone differently.

  • Group estimated-occupancy, starts at the earliest offset, commits by hand. After an outage the missed counts are read from the topic.
  • An unreadable or refused message is dropped and committed. A store failure is not committed: the consumer reconnects after 5 s and reads it again.

Building registration: kernel/registration.rs

A building must exist here before its sensors can be set up. Two entries lead to one use case, Registration::register.

pub async fn register(&self, building_id: &str, payload: &Value) -> Result<(), DomainError> {
    let request = RegistrationRequest::deserialize(payload)
        .map_err(|error| DomainError::Validation(format!("registration payload: {error}.")))?;

    if request.name.trim().is_empty() {
        return Err(DomainError::Validation("name: must be a non-empty string.".to_owned()));
    }
    // Postgres refuses NUL in text, and a store error is retried, so it would block the topic.
    if std::iter::once(&request.name)
        .chain(request.rooms.iter().flat_map(|room| [&room.id, &room.name]))
        .any(|text| text.contains('\0'))
    {
        return Err(DomainError::Validation("name, rooms: must not contain a NUL character.".to_owned()));
    }

    self.buildings.upsert(&RegisteredBuilding { id: building_id.to_owned(), name: request.name,
        rooms: request.rooms.into_iter().map(|room| Room { id: room.id, name: room.name }).collect() }).await?;

    if let Some(max_temperature) = request.max_temperature {
        let mut patch = Bounds::new();
        patch.insert("maxTemp".to_owned(), max_temperature.into());
        self.thresholds.upsert(building_id, None, "temperature", &patch).await?;
    }
    Ok(())
}
  1. Parse the request. Bad shape: 400-class error.
  2. The name must not be blank.
  3. No NUL character in any name or id. PostgreSQL refuses a NUL in text, a store error would be retried for ever, and that would block the whole topic. So anything the database would refuse is checked first.
  4. Save the building and its rooms (an upsert, so registering twice gives the same rows).
  5. If maxTemperature came with it, save it as the building’s maxTemp. (Twin does not send it over Kafka today, but the field stays: it is optional, not dead.)

The Kafka path

pub async fn register_from_event(&self, building_id: &str, payload: &Value) -> anyhow::Result<bool> {
    // A store outage is not the request's fault: answering `failed` would delete the twin.
    let outcome = match self.register(building_id, payload).await {
        Err(DomainError::Internal(error)) => return Err(error),
        outcome => outcome.map_err(|error| error.to_string()),
    };
    let registered = outcome.is_ok();
    self.events.publish_completed(building_id, outcome).await?;
    Ok(registered)
}
  • An invalid request is answered failed with the reason. digital-twin then deletes the building.
  • A store error (Internal) is returned as an error and is not answered. The consumer does not commit, reconnects after 5 s and reads the message again. A database outage is not the building’s fault, and answering failed would delete a good building.
  • A room without an id is dropped. A room without a name takes its id.
  • The second entry is the HTTP PUT /thresholds/buildings/{id} that digital-twin calls after an edit. It is the same register.

Each patch is checked by Thresholds::checked: every key must be a bound of that metric’s plugin, and every value a number. {"maxTmp": 28} on temperature is 400 maxTmp: not a bound of temperature. Because the check asks the plugin which keys exist, a new metric needs no change here.

CachedThresholds sits in front of the store:

  • resolve answers from a cache of up to 10 000 entries, each at most 60 s old. One tick asks PostgreSQL once, only for the rooms not cached.
  • Any write for building b1 and metric temperature drops every cached room of b1 / temperature, because a building row is the fallback for all rooms.
  • Another copy of the service sees the change within 60 s.

Sensors batch

A batch of changes follows the same idea as ingest: check everything, then write everything, or nothing.

  • Building not registered: 404.
  • Any item bad: 422 {"errors":[{"ref","field","message"}]}, nothing written. The ref lets the screen put each message next to the right row.

  • roomId null means outdoors.
  • Positions are not stored here. They belong to digital-twin, under the same sensorId.

Simulation

telemetry does not simulate anything itself. It tells each simulator what to simulate, at start, and only then.

  • Every simulator is told, an empty list included: empty means stop, so a removed sensor stops producing.
  • Outdoor sensors and kinds no simulator claims are left out.
  • Simulation::new refuses a kind that is not a device, or one claimed twice (that would double the readings).
  • All calls run at the same time with a 5 s timeout. All are tried, and then any failure is 502.
  • No simulator configured (Kubernetes): start and stop answer 404.
  • Status: running when any simulator says so. One that does not answer counts as not running.
  • Sensors edited during a run are simulated from the next start.

The body never carries coordinates: positions are digital-twin’s. Body shape: Telemetry Schema, fixture-only shapes.

Device commands

The kernel checks the command against the plugin’s action list (the same FieldSpec checks as for readings). The adapter then turns it into a real call for that kind of device, using bindings.json.

  • No “back within limits” message.
  • A repeated batch alerts again. The insert drops duplicates, but breaches and the tick are sent a second time.
