registry is a small Go service in backend/registry, with its own PostgreSQL database. It answers one question: which organizations exist, and what state is each one in?

It builds nothing. When an organization signs up, registry writes it down as “not built yet”. Then provisioner reads that list, builds what is missing, and comes back to say “done” or “failed”.

  • No route at the edge. Only callers inside the network reach it.
  • Makes no outbound call. It only answers.
  • Owns one table: organizations.

For the business side, read Identity & Tenancy first.

The idea in one minute

Think of a guest book at the door of a building.

  • A new customer arrives and writes a line: name, how they want to be hosted, who checks their passwords. The line says “not built yet”.
  • The clerk (provisioner) walks by every 15 seconds and reads all the “not built yet” lines.
  • After the work is done, the clerk goes back to the book and writes “ready” next to the line. If it went wrong, “failed”, with a short reason.
  • Later, if the customer stops paying, someone writes “suspended”.

registry is the guest book. It does not do the work, it does not decide who may do it, and it never calls anybody. It only keeps the lines true.

The dotted line is dotted because nothing in the repository calls suspend yet. The route exists and works; it just has no caller.

Why a separate service for a list

It would be simpler to keep organizations inside tenancy. They are kept apart on purpose.

  • Different questions. tenancy answers “who belongs to which domain, and what may they do?”. registry answers “which customers exist, and are they set up?”. One question per service.
  • Different life. An organization exists before its domain does. It can also outlive it: a suspended customer keeps its line in the book.
  • Signup stays fast. Signup is one insert. The slow part (building the domain) happens later, somewhere else. See Provisioner.

The table

One table, organizations. Here is the real migration, migrations/0001_init.up.sql:

create table organizations (
  id             uuid primary key default gen_random_uuid(),
  name           text not null unique,
  display_name   text not null,
  tier           text not null check (tier in ('pooled', 'dedicated', 'on-prem')),
  host           text,
  identity_mode  text not null default 'platform' check (identity_mode in ('platform', 'byo-idp')),
  issuer         text,
  license_status text not null default 'active' check (license_status in ('active', 'suspended', 'expired')),
  status         text not null default 'provisioning' check (status in ('provisioning', 'ready', 'failed', 'suspended')),
  status_detail  text,
  created_at     timestamptz not null default now()
);

Column by column:

ColumnRuleWhy
iduuid, made by the databaseCallers never invent ids. gen_random_uuid() runs on insert
namerequired, uniqueThe short name (northfield). Becomes the domain name later, so two organizations cannot share it
display_namerequiredThe human name (Northfield Library)
tierone of three valuesThe database refuses anything else, even if the code forgets to check
hostoptionalNothing writes it today
identity_modeplatform by default, or byo-idpplatform: Ambitwin’s Keycloak checks passwords. byo-idp: the organization’s own provider does
issueroptionalThe address of that own provider, when there is one
license_statusactive by defaultWhether the customer may use the product
statusprovisioning by defaultHow far the setup got
status_detailoptionalA short reason, filled when status is failed
created_atset by the databaseWhen the line was written

There are two states on one row, and they mean different things:

  • status: setup progress. Only provisioner sets ready or failed.
  • license_status: may they use it. Only suspend changes it today.

Nothing leaves failed or suspended. Nothing sets expired.

func Load() (Config, error) {
	dbURL := os.Getenv("DATABASE_URL")
	if dbURL == "" {
		return Config{}, fmt.Errorf("DATABASE_URL is required")
	}
	secret := os.Getenv("INTERNAL_SIGNING_SECRET")
	if secret == "" {
		return Config{}, fmt.Errorf("INTERNAL_SIGNING_SECRET is required")
	}

The database URL and the secret are required. If one is empty, Load returns an error that names it, and the process stops at start. A service that starts without a database, or signs with an empty key, fails later in a confusing way. It is better to stop early.

	addr := os.Getenv("ADDR")
	if addr == "" {
		addr = ":3000"
	}
	return Config{Addr: addr, DatabaseURL: dbURL, InternalSecret: []byte(secret)}, nil
}

The listen address is the only value with a default: :3000, which means “port 3000 on every network interface”. The secret becomes []byte because the signature code wants bytes.

store.go and postgres.go: the part that touches the database

The type and the port

type Organization struct {
	ID            string
	Name          string
	DisplayName   string
	Tier          string // "pooled" | "dedicated" | "on-prem"
	Host          string
	IdentityMode  string // "platform" | "byo-idp"
	Issuer        string
	LicenseStatus string // "active" | "suspended" | "expired"
	Status        string // "provisioning" | "ready" | "failed" | "suspended"
	StatusDetail  string
}

One organization, as the rest of the code sees it. One field per column. Every field is a plain string: an optional column that is empty in the database is "" here, not a special “nothing” value.

type Store interface {
	Create(ctx context.Context, org Organization) (Organization, error)
	Get(ctx context.Context, id string) (Organization, error)
	Pending(ctx context.Context) ([]Organization, error)
	SetStatus(ctx context.Context, id, status, detail string) error
	SetLicenseStatus(ctx context.Context, id, licenseStatus string) error
}

The port: five things the service may ask of “the storage”. There is no SQL and no pgx in sight. The service is written against this list, and tests give it a fake.

Writing a new line: Create

func (p *Postgres) Create(ctx context.Context, org Organization) (Organization, error) {
	err := p.pool.QueryRow(ctx, `
		insert into organizations (name, display_name, tier, host, identity_mode, issuer, license_status, status)
		values ($1, $2, $3, nullif($4, ''), $5, nullif($6, ''), $7, $8)
		returning id`,
		org.Name, org.DisplayName, org.Tier, org.Host, org.IdentityMode, org.Issuer, org.LicenseStatus, org.Status,
	).Scan(&org.ID)
	return org, err
}
  • insert … returning id writes the line and gets back the id the database made, in one round trip.
  • $1, $2, … are placeholders. The values travel apart from the SQL text, so a name like x'); drop table organizations; -- is just a strange name, never code.
  • nullif($4, '') turns an empty string into NULL. So an empty host or issuer is stored as “nothing”, not as an empty text.
  • .Scan(&org.ID) puts the returned id into the struct, and the function returns the struct.

Reading: Get and Pending

func (p *Postgres) Get(ctx context.Context, id string) (Organization, error) {
	var org Organization
	err := p.pool.QueryRow(ctx, `
		select id, name, display_name, tier, coalesce(host,''), identity_mode,
		       coalesce(issuer,''), license_status, status, coalesce(status_detail,'')
		from organizations where id = $1`, id,
	).Scan(&org.ID, &org.Name, &org.DisplayName, &org.Tier, &org.Host, &org.IdentityMode,
		&org.Issuer, &org.LicenseStatus, &org.Status, &org.StatusDetail)
	if errors.Is(err, pgx.ErrNoRows) {
		return Organization{}, ErrNotFound
	}
	return org, err
}
  • coalesce(host,'') is the mirror of nullif: a NULL in the database becomes "" in Go.
  • No row found is a normal event, not a crash. pgx says ErrNoRows, and the store turns it into its own ErrNotFound. Upper layers match on that one, so they never need to know about pgx.
func (p *Postgres) Pending(ctx context.Context) ([]Organization, error) {
	rows, err := p.pool.Query(ctx, `
		select id, name, display_name, tier, coalesce(host,''), identity_mode,
		       coalesce(issuer,''), license_status, status, coalesce(status_detail,'')
		from organizations where status = 'provisioning'`)
	if err != nil {
		return nil, err
	}
	defer rows.Close()

	var out []Organization
	for rows.Next() {
		var org Organization
		if err := rows.Scan(&org.ID, &org.Name, &org.DisplayName, &org.Tier, &org.Host, &org.IdentityMode,
			&org.Issuer, &org.LicenseStatus, &org.Status, &org.StatusDetail); err != nil {
			return nil, err
		}
		out = append(out, org)
	}
	return out, rows.Err()
}

The same select, many rows. The where status = 'provisioning' is the whole meaning of “pending”. defer rows.Close() gives the connection back to the pool when the function ends. rows.Err() at the end catches an error that happened while reading, after the loop.

Note there is no order by and no limit. The list comes back in whatever order Postgres likes, and all at once.

Changing: SetStatus and SetLicenseStatus

func (p *Postgres) SetStatus(ctx context.Context, id, status, detail string) error {
	tag, err := p.pool.Exec(ctx,
		`update organizations set status = $2, status_detail = nullif($3, '') where id = $1`,
		id, status, detail)
	if err != nil {
		return err
	}
	if tag.RowsAffected() == 0 {
		return ErrNotFound
	}
	return nil
}
  • One update changes both status and status_detail.
  • RowsAffected() == 0 means no line has that id. That is ErrNotFound, and later a 404.
  • Because of nullif, passing an empty detail clears the old reason. That is how ready wipes an old failure.

SetLicenseStatus is the same shape, for the license_status column.

registry.go: the rules

The service is short, and its job is to hold the rules.

var validTiers = map[string]bool{"pooled": true, "dedicated": true, "on-prem": true}

A set of the three tiers the product knows. A map[string]bool is the usual Go way to write “is this word in the list?”.

Signup

func (s *Service) Signup(ctx context.Context, in SignupInput) (store.Organization, error) {
	if !validTiers[in.Tier] {
		return store.Organization{}, ErrInvalidTier
	}
	identityMode := in.IdentityMode
	if identityMode == "" {
		identityMode = "platform"
	}
	return s.store.Create(ctx, store.Organization{
		Name: in.Name, DisplayName: in.DisplayName, Tier: in.Tier,
		IdentityMode: identityMode, Issuer: in.Issuer,
		LicenseStatus: "active", Status: "provisioning",
	})
}

In order:

  1. If the tier is not one of the three, stop with ErrInvalidTier. (The table would refuse it too, but a clean error beats a database error.)
  2. If no identity mode came in, use platform.
  3. Write the line with license_status = active and status = provisioning. A caller can not choose these two: every new organization starts “licensed, not built”.

Worked example. Signup with {"name":"northfield","displayName":"Northfield Library","tier":"pooled"}:

Status changes

func (s *Service) MarkReady(ctx context.Context, id string) error {
	return s.store.SetStatus(ctx, id, "ready", "")
}

func (s *Service) MarkFailed(ctx context.Context, id, detail string) error {
	return s.store.SetStatus(ctx, id, "failed", detail)
}

ready passes an empty detail, so any old reason disappears. failed keeps the reason it was given.

Suspend

func (s *Service) Suspend(ctx context.Context, id string) error {
	if err := s.store.SetLicenseStatus(ctx, id, "suspended"); err != nil {
		return err
	}
	return s.store.SetStatus(ctx, id, "suspended", "")
}

Two writes, one after the other:

  1. license_status = 'suspended'. If this fails, stop. status is untouched.
  2. status = 'suspended', with an empty detail.

These two are not in one transaction. If step 2 fails, the license is suspended but status still says ready. See Gaps.

handler.go: HTTP in, status codes out

Routes

func Mount(r chi.Router, svc *service.Service, internalSecret []byte) {
	h := &handler{svc: svc}

	r.Post("/organizations", h.signup)

	r.Group(func(r chi.Router) {
		r.Use(authcontracts.RequireSignature(internalSecret))
		r.Get("/internal/organizations/pending", h.pending)
		r.Post("/internal/organizations/{id}/status", h.setStatus)
		r.Post("/internal/organizations/{id}/suspend", h.suspend)
	})
}
  • /organizations is open to anyone who can reach the service.
  • The three /internal/… routes sit inside a group that uses RequireSignature. A request without a matching signature never reaches the handler.
  • {id} in a path is a chi placeholder; the handler reads it with chi.URLParam.

Signup handler

func (h *handler) signup(w http.ResponseWriter, r *http.Request) {
	var in service.SignupInput
	if err := json.NewDecoder(r.Body).Decode(&in); err != nil {
		http.Error(w, "bad body", http.StatusBadRequest)
		return
	}
	org, err := h.svc.Signup(r.Context(), in)
	if errors.Is(err, service.ErrInvalidTier) {
		http.Error(w, err.Error(), http.StatusBadRequest)
		return
	}
	if err != nil {
		http.Error(w, "signup failed", http.StatusInternalServerError)
		return
	}
	writeOrg(w, http.StatusCreated, org)
}
  1. Read the JSON body into SignupInput. Broken JSON is 400 bad body.
  2. Call the service.
  3. A tier problem is the caller’s mistake: 400 invalid tier.
  4. Any other error is ours, and the caller learns nothing more than 500 signup failed. The real error stays out of the answer.
  5. Success: 201 plus the new organization.

SignupInput has no JSON tags. Go’s JSON reader ignores letter case on keys, so the key displayName fills the field DisplayName.

Request and answer:

{"name":"northfield","displayName":"Northfield Library","tier":"pooled","identityMode":"platform","issuer":""}
{"id":"6f1c0a52-…","name":"northfield","displayName":"Northfield Library","tier":"pooled","status":"provisioning","licenseStatus":"active"}

The answer is built by writeOrg, which lists exactly six fields. identityMode and issuer do not come back.

The decisions in signup, as a picture:

Two failures that surprise people:

  • A second signup with the name northfield. The unique rule rejects the insert. The caller gets 500 signup failed, not a “name taken” answer. See Gaps.
  • identityMode: "sso". The service passes it through, the table’s check refuses it, and the caller gets 500.

Pending handler

func (h *handler) pending(w http.ResponseWriter, r *http.Request) {
	orgs, err := h.svc.Pending(r.Context())
	if err != nil {
		http.Error(w, "internal error", http.StatusInternalServerError)
		return
	}
	w.Header().Set("Content-Type", "application/json")
	out := make([]map[string]string, len(orgs))
	for i, org := range orgs {
		out[i] = map[string]string{
			"id": org.ID, "name": org.Name, "displayName": org.DisplayName,
			"tier": org.Tier, "identityMode": org.IdentityMode, "issuer": org.Issuer,
		}
	}
	_ = json.NewEncoder(w).Encode(out)
}

Ask the service for the list, turn each organization into a small map, write it as JSON. Six fields go out, and they are the fields provisioner reads. For northfield the answer looks like:

[{"id":"6f1c0a52-…","name":"northfield","displayName":"Northfield Library","tier":"pooled","identityMode":"platform","issuer":""}]

Note: with nobody pending, out is an empty slice, so the answer is [] and not null.

Status handler

func (h *handler) setStatus(w http.ResponseWriter, r *http.Request) {
	var body struct {
		Status string `json:"status"`
		Detail string `json:"detail"`
	}
	if err := json.NewDecoder(r.Body).Decode(&body); err != nil {
		http.Error(w, "bad body", http.StatusBadRequest)
		return
	}

Read {"status": …, "detail": …}. Broken JSON is 400.

	id := chi.URLParam(r, "id")
	var err error
	switch body.Status {
	case "ready":
		err = h.svc.MarkReady(r.Context(), id)
	case "failed":
		err = h.svc.MarkFailed(r.Context(), id, body.Detail)
	default:
		http.Error(w, `status must be "ready" or "failed"`, http.StatusBadRequest)
		return
	}

Take the id from the path, then branch on the status. Only two words are accepted. Anything else, an empty value included, is 400 and nothing is written.

That is on purpose. provisioner is the only caller and it reports exactly these two outcomes. Treating “anything else” as ready would mark a customer live because of a typo.

	if errors.Is(err, service.ErrNotFound) {

The database row goes from status = provisioning, status_detail = NULL to status = failed, status_detail = 'tenancy provisioning failed: …'. The answer is 204, and the organization is no longer listed by GET …/pending.

Suspend handler

func (h *handler) suspend(w http.ResponseWriter, r *http.Request) {
	err := h.svc.Suspend(r.Context(), chi.URLParam(r, "id"))
	if errors.Is(err, service.ErrNotFound) {
		http.Error(w, "not found", http.StatusNotFound)
		return
	}
	if err != nil {
		http.Error(w, "internal error", http.StatusInternalServerError)
		return
	}
	w.WriteHeader(http.StatusNoContent)
}

No body needed. Same answers as the status handler.

The signature check

RequireSignature(secret) wraps the three /internal/… routes. It lives in auth-contracts, so registry writes none of this itself:

  1. No X-Signature header: 403 missing signature.
  2. Read the whole body, then put the bytes back so the handler can read them too.
  3. Compute hex(HMAC-SHA256(secret, body)) and compare it with the header. The comparison (hmac.Equal) takes the same time whatever the input, so the answer time gives no hint.
  4. Different: 403 invalid signature. Same: run the handler.

Example. GET …/pending has no body, so the signature is over empty bytes. With the fixture secret an-internal-secret-that-is-at-least-32-bytes (from schemas/fixtures/internal-signature.json) the right header is:

X-Signature: 52a0b3efd233aae8d54e811f3e10623f119e3978fd9411c10174b8e5307607b7

Why not a normal login? These calls come from another service, with no person behind them. A shared secret is the simplest proof that fits. For the full story see Auth Contracts.

Load config (stop if broken). Make a context that ends on Ctrl+C or SIGTERM, the signal Docker and Kubernetes send when they stop a container.

if err := runMigrations(cfg.DatabaseURL); err != nil {
	log.Fatalf("migrations: %v", err)
}

Before anything else, bring the database up to date. The helper:

func runMigrations(databaseURL string) error {
	m, err := migrate.New("file://migrations", databaseURL)
	if err != nil {
		return err
	}
	if err := m.Up(); err != nil && err != migrate.ErrNoChange {
		return err
	}
	return nil
}

migrate reads the files in migrations/ and runs those not yet applied. “Nothing new to apply” (ErrNoChange) is not an error: that is the normal case on every start after the first. Any other error stops the process, so the service never runs on a half-built database.

pool, err := pgxpool.New(ctx, cfg.DatabaseURL)

Open a connection pool, wrap it in the Postgres store, hand that to the service. This is the one place where the real database meets the rules.

Make the router. /health answers 200 and nothing else. Then mount the real routes.

The unit tests need no database because service talks to the Store port and tests plug in storefake. The integration tests exist for the one thing a fake cannot prove: that the real SQL does what the fake pretends.

Gaps

  • Duplicate name is 500. The unique rule fires, but nothing turns it into a “name taken” answer. The caller cannot tell a duplicate from a crash.
  • Unknown identity mode is 500. Only the database check refuses it.
  • A malformed id is 500, not 404. The id column is a uuid. Postgres refuses text that is not shaped like one, and that error is not mapped. This comes from reading the code, not from a test.
  • No caller for signup. Nothing in the repository calls POST /organizations, and the edge has no route to it.
  • Suspend is two writes, not one transaction. A failure between them leaves license_status = suspended and status = ready.
  • pending has no order by and no limit. Fine today with a handful of organizations.
  • host and expired are never set.
