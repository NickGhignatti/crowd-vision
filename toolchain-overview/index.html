A change from editor to cluster

Example. A developer fixes a bug in backend/telemetry/src/kernel/ingest.rs and wants it running in the local cluster.

What happens at each step

StepWhoWhat happens
1justFinds recipe affected in just/lint.just. It first runs recipe workflows, which checks .github/workflows/ against .github/services.json
2miseReads .mise.toml, puts Rust 1.99.1, Go 1.27.3, Node 24, Python 3.14.8, uv 0.13.5 and moon 2.6.4 first on PATH
3moonStarts with the pinned tools for itself and every child it starts
4moonAsks git for changed files, matches them against each task’s inputs
5cargoLints only telemetry. A warning fails the run
6–8moon, cargoSame for tests. telemetry:test runs unit tests plus tests/architecture.rs, never the database tests
9DeveloperOpens a pull request to master
10ci-gate.ymlWorks out the changed services from paths, using .github/services.json
11tpl-rust-ci.ymlReads the Rust pin from .mise.toml, then runs the checks for that service only
12ci-gate.ymlBuilds the service image to prove the Dockerfile still works
13DeveloperMerges
14–15cd-release.ymlrelease-please reads fix(telemetry): … and prepares the next version
16cd-registry.ymlBuilds every changed service’s image and pushes it to ghcr.io
17–19just, kubectlA restart makes the pods pull :latest again
20ClusterThe fix runs
  • Nothing deploys by itself. The cluster changes only when a person runs just k8s restart or just k8s apply.
  • Steps 1 to 8 are local and optional. Steps 10 to 12 run anyway, so a skipped local check shows up in the pull request.

Rules for every change

A change that breaks one is rejected, even with CI green. The rules for the structure itself are in Architecture Overview.

RuleWhat it meansWhy
Tools only through mise and justjust <recipe> or mise exec -- <tool>, never a tool found on the machine’s PATHAnother version gives other lint and test results
Test what changesRust: #[cfg(test)] and tests/. Go: *_test.go. Python: tests/. Frontend: src/utils/** with *.spec.ts beside the fileBehaviour with no test can break unseen
Frontend unit tests cover pure logic onlyScreens are covered by frontend/e2e/ (Playwright) and backend/acceptance/A component test checks markup, not behaviour
Docs change in the same commit as the codeThe matching documentation/**.qd page moves with the codeDocs fixed later are never fixed
Conventional Commitsfeat(twin): …, scopes in Namingrelease-please reads the type; a bad message is silently “no release”
New package registered once.moon/workspace.yml and .github/services.jsonmoon and CI see only what is listed

Two pins live outside the mise file

CI’s setup-node asks for Node 24.x, and setup-python reads .python-version (3.14). Both agree with .mise.toml today, but nothing checks it. just itself is not pinned: CI installs 1.42.4.

Naming

A name says what a thing is, so a reader can guess its role without opening it. Linters check the code style of each language; review checks everything else on this page.

A service has one short name, the same on every surface, with no -service suffix.

SurfaceExample
Directorybackend/telemetry, backend/digital-twin
Cargo crate, Go module, binarytelemetry, digital-twin
moon projecttelemetry, digital-twin

Commit scopes

The scope is the service or area, so history can be filtered by part:

gateway, tenancy, registry, provisioner, twin, telemetry, dashboard, notification, socket, chat, frontend, agent, ci, docs, k8s.

feat(twin): add per-room colour overrides
fix(gateway): reject expired refresh tokens

Nothing in CI checks the format. A malformed message is silently treated as “no release”: Release Please.

Renaming carries data

Some names own stored state. Changing one starts from empty, with no error.

NameWhat a rename does
Compose volumeCompose builds the real name from the project and the declared name. A new name mounts a new, empty volume and leaves the old one with all the data. Move the data in the same change
Kafka consumer groupA group with no saved position starts from the oldest message: the whole topic is read again. Harmless for registrations. For alerts it sends old breaches again, only held back by the 5-minute cooldown
Database nameA rename is a migration, so names stay: chatdb, twindb, notificationdb
System identitysystem:notification-service keeps its old name: a test pins it byte for byte, and logs keep one stable source

dashboard ignores the database in its URI

Its compose MONGO_URI ends in /contractsdb, but infra/db.rs always opens database crowdvision, collection preferences. The path in the URI changes nothing.

Check for orphans after a rename

docker volume ls lists every volume. One no compose file names is orphaned: move its data or delete it on purpose.
