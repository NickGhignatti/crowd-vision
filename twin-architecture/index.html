Realises the Building Management domain. Rust, MongoDB. Code-level page: Digital Twin Service.

The source of truth for the shape of every building. Other services add live data on top of it.

Who talks to it

Thin: a request. Thick: Kafka. Dotted: Redis.

It also calls three services directly:

Inside

  • Entities hold what is true of a building whatever the storage, like “a room has a size above zero”.
  • Use cases are the actions, like “register” or “update”, plus the ports they need.
  • Access rules run in the core. “May Ada edit this building?” is a rule, and Cedar needs no network.
  • Arrows point inward. Only the start-up code knows the store is MongoDB. Tests swap in fakes and need no database.
  • A test fails the build if a layer imports the wrong way.

Registering a building

StepWhy this way
Check before answeringA building the service would refuse is never accepted
Answer before buildingBuilding is slow, and can fail for reasons Ada cannot fix
Ada polls the handleShe sees ready or failed, never silence
Announce on Kafka, do not calltelemetry can be down; the request waits for it
Ready only on the answerSending the request is not success. telemetry saying “done” is
  • Three entries, one use case. HTTP, the worker and the Kafka answer all go through the same registration logic, so the three cannot drift apart.
  • Twice is the same as once. A message can come twice. Building again ends in the same one building.
  • Best effort extras. Starting columns in dashboard and room limits are sent after; a failure is logged, not fatal.

Estimating phones from Wi-Fi

Each tick says which routers hear which phone, and how loud.

  1. The floor is split into small cells. For each cell, the service knows how loud each router should sound there, walls included.
  2. Each phone gets the cell that best matches what the routers heard.
  3. A phone cannot jump faster than a person walks, so its last place narrows the choice.
  4. A phone unseen for a few ticks is dropped. One missed poll does not end it.

Example. Router A hears a phone loud, router B faint. The cells near A and far from B score best. Last tick the phone was in room 2, next door, so room 2 wins over the hall beyond it.

  • A tick older than three polls is skipped: it shows where people were, not where they are.
  • Nothing is stored. Dots go to socket, room counts back to telemetry.

Choices

ChoiceWhy
The service makes building idsThe id never depends on what a client or a database chose
Owners come from the passNo call to identity services per request
Shape treated as fixedOnly names and owners change; the live data lives elsewhere
Same size checks on every writeA bad room is refused with a clear error, never stored

Gaps

  • Code vs domain: rooms cannot be edited. The domain says staff edit rooms. The code fixes them at upload.
  • Code vs domain: starting Focus is a direct call to dashboard, best effort, not a reaction to “Building Ready”. If it fails, the building gets no live feed until someone saves its columns.
  • The request rate limit lives in memory. Two copies of the service would each allow the full rate.
