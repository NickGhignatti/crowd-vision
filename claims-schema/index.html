Rust crate at schemas/claims-schema. It reads the x-gateway-claims header for every Rust service. Go has the same job in Auth Contracts, Python in agent/app/auth.py: one reader per language, never one per service.

Depends only on serde, serde_json, base64. No I/O, no web framework.

notificationsame as digital-twinaccountName required, else 401 …missing an account
socketClaimsPayload::decode, CLAIMS_HEADERsub and accountName required, else the connection is refused

The crate only reads. Deciding which field is required is each service’s job, because the services need different things: notification keys subscriptions by account name, the others key on sub.

Shape

pub const CLAIMS_HEADER: &str = "x-gateway-claims";

pub struct Membership {
    pub domain: String,
    pub role: Option<String>,
    pub external_id: Option<String>,   // "externalId"
}

pub struct ClaimsPayload {
    pub sub: Option<String>,
    pub account_name: Option<String>,  // "accountName"
    pub sid: Option<String>,
    pub memberships: Vec<Membership>,
}

Field for field the same as Go’s StandardClaims. Every field is optional in the type: parsing says what the header says, the service says whether that is enough.

Two reading choices

Four base64 alphabets

decode_claims_header tries four decoders in order and keeps the first that works:

OrderAlphabetPadding
1STANDARD (+ /)required
2URL_SAFE (- _)required
3STANDARD_NO_PADnone
4URL_SAFE_NO_PADnone

A Rust decoder accepts exactly one form. The edge may write any of them, so trying only one would refuse good headers.

Bad memberships are dropped, not fatal

Example. ["acme", {"domain":7}, {"role":"admin"}, {"domain":"beta"}] keeps only beta, with no role.

Why: failing the whole header turns “not a member of that domain” (403) into “broken token” (401). The person debugging then looks in the wrong service. A memberships that is not a list at all is still fatal: that is a broken token.

A blank string is treated as missing, so " " can never act as an identity.

What stays in each service

  • The extractor and its error type. Axum’s FromRequestParts is a trait from another crate, and Rust forbids implementing it for this crate’s types from a service. The error types also differ: StatusCode in dashboard, DomainError in the others.
  • Access rules. Cedar entities, the system: callers, which field is required. A shape crate that grows rules ties every service to every other.

Building a service that uses it

The dependency is a path, ../../schemas/claims-schema, so each consumer image builds from the repo root (cd_context: "." in .github/services.json). Each Dockerfile copies the crate before cargo chef prepare and before each cargo chef cook; a path missing during cook fails the build half way.

Gaps

  • The other languages accept fewer alphabets. Go’s RequireMeshClaims takes standard base64 only, and Python’s agent/app/auth.py uses base64.b64decode, also standard. A header these four alphabets accept in Rust can be refused in tenancy or agent.
  • role_in takes the first match. If one domain appears twice with two roles, Rust and Go’s RoleIn give the first, while tenancy’s own roleIn gives the highest.
