claims-gateway is a Go service in backend/claims-gateway. It does one big thing: it swaps a Keycloak sign-in for the platform’s own token, called the internal JWT.

It is also the only service that checks a JWT signature. Every other service trusts what the edge passes on.

  • No database. Accounts live in Keycloak. Memberships live in tenancy.
  • Edge route /gateway/*, not gated. A browser has no token before it signs in, so the door has to be open.

For the business side, read Identity & Tenancy first.

The idea in one minute

Think of a theatre.

  • Keycloak is the box office. It checks a visitor’s ID and sells the ticket. It knows who the visitor is.
  • But the actors, the lights, the bar (every other service) do not want to call the box office for every question. And they do not know which seats a visitor may sit in.
  • So at the door, the gateway takes the box-office ticket, asks the seating plan (tenancy) which rooms the person may enter and as what, and stamps a wristband: the internal JWT. The wristband holds the name, an id, and the list of rooms with a role in each.
  • From then on, a guard at the entrance (the edge) looks at the wristband once, and tells everybody inside what it says. Nobody inside checks the stamp again.
  • The wristband is good for 15 minutes. While the person stays, the browser swaps it for a fresh one every 10 minutes (that is refresh).

Steps 1 to 5 happen once per sign-in. Steps 6 to 8 happen on every request.

The internal JWT

This is the product of the service. A decoded one looks like this:

{"sub":"a1b2c3d4-…","accountName":"Ada Lovelace","sid":"5e0f…","memberships":[{"domain":"northfield","role":"business_admin"}],
 "iss":"cv-gateway","iat":1793613600,"exp":1793614500}
ClaimComes fromRule
subKeycloak user idEvery reader requires it
accountNameKeycloak name, else preferred_usernameDisplay only
sidA new UUID at sign-inKept on refresh and profile edit
membershipstenancyNever null. No membership is []
issGATEWAY_ISSUERDefault cv-gateway
iat, expThe clockexp = iat + 15 min (900 s)

The header says alg: RS256 and kid = GATEWAY_KEY_ID (default cv-gateway-1).

It travels in two ways:

  • The authentication_token cookie: HttpOnly (page scripts cannot read it), Secure (HTTPS only), SameSite=Lax (not sent on most cross-site requests), path /, and no Max-Age, so it goes away when the browser closes.
  • From sign-in routes only, also in the JSON body: {"token":"…"}.

signer.go: making the wristband

func (s *Signer) Sign(claims authcontracts.StandardClaims, ttl time.Duration) (string, error) {
	if claims.SID == "" {
		claims.SID = uuid.NewString()
	}
	memberships := claims.Memberships
	if memberships == nil {
		memberships = []authcontracts.Membership{}
	}

Two safety nets before signing. A missing session id gets a new random one. A nil list of memberships becomes an empty list, so the JSON says [] and never null. Readers in other languages would trip on null.

	tok := jwt.NewWithClaims(jwt.SigningMethodRS256, jwt.MapClaims{
		"sub":         claims.Sub,
		"accountName": claims.AccountName,
		"sid":         claims.SID,
		"memberships": memberships,
		"iss":         s.issuer,
		"iat":         time.Now().Unix(),
		"exp":         time.Now().Add(ttl).Unix(),
	})
	tok.Header["kid"] = s.kid // Signer's key ID
	return tok.SignedString(s.key)
}

Build the token with the seven claims, add the key id (kid) to the header, and sign it with the private RSA key. iat and exp are seconds since 1970. The kid lets a reader pick the right public key when more than one is published.

func (s *Signer) JWKS() []byte {
	jwk, err := jwkset.NewJWKFromKey(&s.key.PublicKey, jwkset.JWKOptions{
		Metadata: jwkset.JWKMetadataOptions{KID: s.kid, ALG: jwkset.ALG("RS256")},
	})
	if err != nil {
		panic("signer: building JWKS from our own key: " + err.Error())
	}
	// … marshal {"keys":[jwk]}
}

Turn the public half of the key into a JWKS document. A failure panics on purpose: the key is always a valid RSA key made by this process, so an error here means the program itself is broken, not that something is wrong at run time.

Worked example. Sign with sub=a1b2…, TTL 900 s at Unix time 1793613600:

FieldValue
iat1793613600
exp1793614500 (that is 900 s later)
memberships[{"domain":"northfield","role":"business_admin"}]

(The time and ids are made up for the example. The shape is real.)

config.go: the environment

The pattern is the same as in the other Go services: every required variable is read, and a missing one stops the process with a message that names it. Required here: OIDC_ISSUER, OIDC_CLIENT_ID, TENANCY_URL, INTERNAL_SIGNING_SECRET, KEYCLOAK_REALM, REGISTRATION_CLIENT_ID, REGISTRATION_CLIENT_SECRET.

Two lines hold the interesting ideas.

discoveryURL := os.Getenv("OIDC_DISCOVERY_URL")
if discoveryURL == "" {
	discoveryURL = issuer // single-hostname deployments: same URL for both
}

Two Keycloak addresses, on purpose. Locally, a browser reaches Keycloak as http://localhost:8090/realms/ambitwin, and that is the iss written inside its tokens. But this container reaches Keycloak as http://keycloak:8080/realms/ambitwin. One name is for checking the token’s iss, the other for making HTTP calls. If both are the same (one hostname), the second variable can be left out.

keycloakBaseURL := strings.TrimSuffix(discoveryURL, "/realms/"+keycloakRealm)

The admin calls need Keycloak’s base address, with no /realms/… on the end. It is cut off the discovery URL.

Where the signing key comes from

func loadOrGenerateKey() (*rsa.PrivateKey, string, error) {
	pemStr := os.Getenv("GATEWAY_PRIVATE_KEY")
	if pemStr == "" {
		if path := os.Getenv("GATEWAY_PRIVATE_KEY_FILE"); path != "" {
			b, err := os.ReadFile(path)
			// …
			pemStr = string(b)
		}
	}
	if pemStr != "" {
		block, _ := pem.Decode([]byte(pemStr))
		// … must be valid PEM, PKCS#8, and an RSA key
		kid := os.Getenv("GATEWAY_KEY_ID")
		if kid == "" {
			kid = "cv-gateway-1"
		}
		return rsaKey, kid, nil
	}

	log.Println("WARNING: GATEWAY_PRIVATE_KEY not set — generating an ephemeral key. …")
	key, err := rsa.GenerateKey(rand.Reader, 2048)
	// …
	return key, "ephemeral-dev-key", nil
}

A generated key changes at every restart, so every cookie signed before it stops working. That is fine on a laptop. In a cluster it would log everybody out at every deploy, which is why the code shouts a warning.

The routes that need a signed-in caller (/me, /refresh, /verify, /profile) check the gateway’s own tokens. So the keys to check them are built straight from the signer’s own public key, with no network call.

oidcverifier.go: checking Keycloak’s ID token

The only package that speaks OIDC.

func New(ctx context.Context, discoveryURL, issuerURL, clientID string) (*Verifier, error) {
	jwksURL, err := discoverJWKSURL(ctx, discoveryURL)
	if err != nil {
		return nil, fmt.Errorf("oidc discovery against %q: %w", discoveryURL, err)
	}
	keySet := oidc.NewRemoteKeySet(ctx, jwksURL)
	verifier := oidc.NewVerifier(issuerURL, keySet, &oidc.Config{ClientID: clientID})
	return &Verifier{inner: verifier}, nil
}
  1. Ask Keycloak where its public keys are (discoverJWKSURL).
  2. Make a key set that fetches and caches them from there.
  3. Make a verifier that demands: iss equals issuerURL, aud holds clientID, the signature checks out, and the token has not expired.

The library is not allowed to do its own discovery because of the two-addresses problem. So discovery is done by hand:

docURL := strings.TrimSuffix(discoveryURL, "/") + "/.well-known/openid-configuration"
// … GET it, decode {"jwks_uri": "..."}
discU, err := url.Parse(discoveryURL)
jwksU, err := url.Parse(doc.JWKSURI)
jwksU.Scheme, jwksU.Host = discU.Scheme, discU.Host
return jwksU.String(), nil

The discovery document may say "jwks_uri": "http://localhost:8090/realms/…/certs", an address this container cannot reach. So the scheme and host are replaced with the ones from discoveryURL: http://keycloak:8080/realms/…/certs.

func (v *Verifier) Verify(ctx context.Context, rawIDToken string) (service.IDTokenClaims, error) {
	tok, err := v.inner.Verify(ctx, rawIDToken)
	if err != nil {
		return service.IDTokenClaims{}, err
	}

	var raw struct {
		PreferredUsername string   `json:"preferred_username"`
		Name              string   `json:"name"`
		EmailVerified     bool     `json:"email_verified"`
		Organization      []string `json:"organization"`
		Roles             []string `json:"roles"`
	}
	if err := tok.Claims(&raw); err != nil {
		return service.IDTokenClaims{}, fmt.Errorf("decoding id token claims: %w", err)
	}

First the checks above. Then read the extra claims the service wants. name and organization are optional: a token without them still verifies.

func firstOrganizationName(orgs []string) string {
	if len(orgs) == 0 {
		return ""
	}
	return orgs[0]
}

Keycloak’s organization claim is a list of names. Only the first is used. A person in two Keycloak organizations is provisioned in the first one only.

tenancyclient.go: asking tenancy

The same shape as in Provisioner: 5 s timeout, signed requests.

func (c *Client) MembershipsFor(ctx context.Context, accountID string) ([]authcontracts.Membership, error) {
	u := c.baseURL + "/internal/memberships?" + url.Values{"accountId": {accountID}}.Encode()
	req, err := http.NewRequestWithContext(ctx, http.MethodGet, u, nil)
	// …
	req.Header.Set(authcontracts.SignatureHeader, authcontracts.Sign(c.secret, nil))

	resp, err := c.http.Do(req)
	if err != nil {
		return nil, fmt.Errorf("tenancy unreachable: %w", err)
	}
	defer resp.Body.Close()

	if resp.StatusCode != http.StatusOK {
		return nil, fmt.Errorf("tenancy returned %d", resp.StatusCode)
	}
	var out []authcontracts.Membership
	if err := json.NewDecoder(resp.Body).Decode(&out); err != nil {
		return nil, fmt.Errorf("decoding memberships: %w", err)
	}
	return out, nil
}

url.Values{…}.Encode() builds accountId=a1b2… with the right escaping. Any failure is an error, never an empty list. That matters: “I could not ask” must not look like “this person has no memberships”, or a tenancy outage would sign everyone in as a nobody. The service turns such an error into 503.

switch resp.StatusCode {
case http.StatusNoContent:
	return nil
case http.StatusForbidden:
	return service.ErrInviteOnly
default:
	msg, _ := io.ReadAll(resp.Body)
	return fmt.Errorf("tenancy returned %d: %s", resp.StatusCode, msg)
}

Provision has three outcomes. 204 is success. 403 is a normal answer: “this domain is invite-only”, which becomes its own error ErrInviteOnly so the service can treat it as “no membership” and not as a failure. Anything else is an error with the body attached to help debugging.

exchange.go: the heart

Exchange: the whole sign-in

func (g *Gateway) Exchange(ctx context.Context, rawIDToken string) (string, error) {
	kc, err := g.verifier.Verify(ctx, rawIDToken)
	if err != nil {
		return "", fmt.Errorf("%w: %v", ErrInvalidIDToken, err)
	}

	memberships, err := g.tenancy.MembershipsFor(ctx, kc.Sub)
	if err != nil {
		return "", fmt.Errorf("%w: %v", ErrTenancyUnavailable, err)
	}

	// The tenancy service has no record but keycloak does.
	if len(memberships) == 0 && kc.Organization != "" {
		memberships, err = g.provisionOnFirstLogin(ctx, kc)
		if err != nil {
			return "", err
		}
	}

	return g.signer.Sign(authcontracts.StandardClaims{
		Sub:         kc.Sub,
		AccountName: accountName(kc),
		SID:         uuid.NewString(),
		Memberships: memberships,
	}, g.ttl)
}

Three steps, with a fallback in the middle:

  1. Verify the Keycloak token. Bad token: ErrInvalidIDToken (401).
  2. Look up the memberships in tenancy. Failure: ErrTenancyUnavailable (503). The service fails closed: no wristband without the seating plan.
  3. First sign-in fallback. If tenancy has no membership for this person, but Keycloak says they belong to an organization, create the membership now (see below).
  4. Sign the wristband with a brand-new sid.

fmt.Errorf("%w: %v", ErrInvalidIDToken, err) keeps the kind of error (%w, so errors.Is works) and the details (%v, for the log).

func accountName(kc IDTokenClaims) string {
	if kc.Name != "" {
		return kc.Name
	}
	return kc.PreferredUsername
}

The display name is the full name when there is one, else the username.

First sign-in through an organization

func (g *Gateway) provisionOnFirstLogin(ctx context.Context, kc IDTokenClaims) ([]authcontracts.Membership, error) {
	role := HighestRole(kc.Roles)
	err := g.tenancy.Provision(ctx, ProvisionRequest{
		AccountID: kc.Sub, DomainName: kc.Organization, Role: role, ExternalID: kc.Sub,
	})
	switch {
	case err == nil:
		return []authcontracts.Membership{{Domain: kc.Organization, Role: role}}, nil
	case errors.Is(err, ErrInviteOnly):
		return []authcontracts.Membership{}, nil
	default:
		return nil, fmt.Errorf("%w: %v", ErrTenancyUnavailable, err)
	}
}
  • Ask tenancy to add the person to the organization’s domain with the role Keycloak gave.
  • Success: the wristband holds that one membership. (No second lookup is needed: the answer is known.)
  • ErrInviteOnly: the domain does not accept self-join. The person signs in with no memberships. Sign-in still works.
  • Anything else, a 404 for a missing domain included: sign-in fails with 503.
func HighestRole(roles []string) string {
	best, bestWeight := "standard_customer", authcontracts.RoleWeights["standard_customer"]
	for _, r := range roles {
		if w, ok := authcontracts.RoleWeights[r]; ok && w > bestWeight {
			best, bestWeight = r, w
		}
	}
	return best
}

Keycloak puts all of a person’s roles in the token, including ones that are not Ambitwin’s (offline_access, uma_authorization). This picks the one with the biggest weight from the ladder, ignores the others, and falls back to standard_customer.

Worked example. Keycloak says organization: ["northfield"], roles: ["business_staff","offline_access"].

StepValue
HighestRolebusiness_staff (60). offline_access is not on the ladder
Request to tenancyPOST /internal/provision {"accountId":"a1b2…","domainName":"northfield","role":"business_staff","externalId":"a1b2…"}
northfield is open-via-idp204
Wristbandmemberships: [{"domain":"northfield","role":"business_staff"}]

If northfield were invite-only, tenancy would answer 403, and the wristband would hold memberships: [].

RefreshSession

func (g *Gateway) RefreshSession(ctx context.Context, current authcontracts.StandardClaims) (string, error) {
	memberships, err := g.tenancy.MembershipsFor(ctx, current.Sub)
	if err != nil {
		return "", fmt.Errorf("%w: %v", ErrTenancyUnavailable, err)
	}
	current.Memberships = memberships
	return g.signer.Sign(current, g.ttl)
}

Take the claims of the still-valid token, replace the memberships with fresh ones from tenancy, sign again. Same sub, same accountName, same sid. Keycloak is not asked.

  • Refresh needs a token that is still valid. An expired one is 401, and the person signs in again.
  • The browser calls it every 10 minutes; a renewal that never reached the gateway is retried after 30 s. Both delays live in utils/authentication/session.ts, and the interval must stay under the 15 min lifetime.
  • It is also called right after a membership change, so the new role shows at once.

Example. Ada signs in at 10:00 (exp 10:15). Refresh at 10:10 gives exp 10:25. Refresh at 10:20 gives 10:35. Her laptop sleeps from 10:21 to 10:40: the cookie expired at 10:35, so the refresh at 10:40 answers 401.

Open and closed doors

r.Group(func(r chi.Router) {

Doors that make a token are open. Doors that use one are inside a group that checks it. “Valid internal JWT” means RequireAuthentication from Auth Middleware:

  1. Take Authorization: Bearer …, else the authentication_token cookie. None: 401 unauthenticated.
  2. Parse it with this service’s own public key. Only RS256; iss must equal GATEWAY_ISSUER; exp must be in the future. Fails: 401 invalid token.
  3. sub empty: 401 invalid token claims.
  4. Put the claims on the request context, for the handler to read.

The exchange handler

func exchangeHandler(gw *service.Gateway) http.HandlerFunc {
	return func(w http.ResponseWriter, r *http.Request) {
		var body struct {
			IDToken string `json:"idToken"`
		}
		if err := json.NewDecoder(r.Body).Decode(&body); err != nil || body.IDToken == "" {
			http.Error(w, "idToken is required", http.StatusBadRequest)
			return
		}

		token, err := gw.Exchange(r.Context(), body.IDToken)
		if err != nil {
			writeAuthError(w, err)
			return
		}
		writeSessionCookieAndToken(w, token)
	}
}

A function that returns a handler, so gw is captured once. Read {"idToken": "…"}, call the service, write the cookie. login and register have exactly the same shape with different fields.

Cookies

func setSessionCookie(w http.ResponseWriter, token string) {
	http.SetCookie(w, &http.Cookie{
		Name: CookieName, Value: token, Path: "/",
		HttpOnly: true, Secure: true, SameSite: http.SameSiteLaxMode,
	})
}

func writeSessionCookieAndToken(w http.ResponseWriter, token string) {
	setSessionCookie(w, token)
	w.Header().Set("Content-Type", "application/json")
	_ = json.NewEncoder(w).Encode(map[string]string{"token": token})
}

Sign-in routes set the cookie and return the token in the body. refresh and PATCH /profile set only the cookie and answer 204. Logout does the opposite of setting it:

http.SetCookie(w, &http.Cookie{
	Name: CookieName, Value: "", Path: "/", MaxAge: -1,
	HttpOnly: true, Secure: true, SameSite: http.SameSiteLaxMode,
})

MaxAge: -1 tells the browser to delete the cookie now. Logout does not invalidate the token itself. See Gaps.

verify: the edge asks

func verifyHandler(w http.ResponseWriter, r *http.Request) {
	claims, ok := authmiddleware.FromContext(r.Context())
	if !ok {
		w.WriteHeader(http.StatusUnauthorized)
		return
	}
	body, err := json.Marshal(claims)
	if err != nil {
		w.WriteHeader(http.StatusInternalServerError)
		return
	}
	w.Header().Set("X-Gateway-Claims", base64.StdEncoding.EncodeToString(body))
	w.WriteHeader(http.StatusOK)
}

By the time this runs, RequireAuthentication has already checked the token. All that is left is: turn the claims back into JSON, encode as base64, put them in the reply header X-Gateway-Claims, answer 200. Caddy copies that header onto the original request as x-gateway-claims.

Errors to status codes

func writeAuthError(w http.ResponseWriter, err error) {
	switch {
	case errors.Is(err, service.ErrInvalidIDToken):
		http.Error(w, "invalid id token", http.StatusUnauthorized)
	case errors.Is(err, service.ErrInvalidCredentials):
		http.Error(w, "invalid credentials", http.StatusUnauthorized)
	case errors.Is(err, service.ErrEmailTaken):
		http.Error(w, "email already registered", http.StatusConflict)
	case errors.Is(err, service.ErrUserNotFound):
		http.Error(w, "account not found", http.StatusNotFound)
	case errors.Is(err, service.ErrTenancyUnavailable), errors.Is(err, service.ErrKeycloakUnavailable):
		http.Error(w, "service unavailable, try again", http.StatusServiceUnavailable)
	default:
		http.Error(w, "internal error", http.StatusInternalServerError)
	}
}

Password sign-in and sign-up

Used by the app’s own forms (frontend/src/composables/authentication/useKeycloakAuth.ts). Both end in Exchange, so every way in gives the same kind of token.

func (g *Gateway) Login(ctx context.Context, username, password string) (string, error) {
	idToken, err := g.authenticator.PasswordGrant(ctx, username, password)
	if err != nil {
		if errors.Is(err, ErrInvalidCredentials) {
			return "", err
		}
		return "", fmt.Errorf("%w: %v", ErrKeycloakUnavailable, err)
	}
	return g.Exchange(ctx, idToken)
}

func (g *Gateway) Register(ctx context.Context, email, password, name string) (string, error) {
	if err := g.registrar.CreateUser(ctx, email, password, name); err != nil {
		if errors.Is(err, ErrEmailTaken) {
			return "", err
		}
		return "", fmt.Errorf("%w: %v", ErrKeycloakUnavailable, err)
	}
	return g.Login(ctx, email, password)
}
  • Login: ask Keycloak for an ID token with the username and password. Wrong password is its own error (401). Any other failure is “Keycloak unavailable” (503). Then run the normal Exchange on that token.
  • Register: create the user first. A taken email is 409. Then Login with the same email and password.

Client credentials means: the gateway itself proves who it is with its client id and secret, with no person involved. It is fetched again for every admin call; nothing is cached. Simple, but it costs one extra round trip per call.

Profile and password

func (g *Gateway) ChangePassword(ctx context.Context, userID, currentPassword, newPassword string) error {
	email, _, _, err := g.profileReader.GetUser(ctx, userID)
	// … not found → ErrUserNotFound, other → ErrKeycloakUnavailable

	if _, err := g.authenticator.PasswordGrant(ctx, email, currentPassword); err != nil {
		if errors.Is(err, ErrInvalidCredentials) {
			return err
		}
		return fmt.Errorf("%w: %v", ErrKeycloakUnavailable, err)
	}

	if err := g.passwordChanger.ResetPassword(ctx, userID, newPassword); err != nil {
		return fmt.Errorf("%w: %v", ErrKeycloakUnavailable, err)
	}
	return nil
}

Changing a password takes three steps: read the user’s email from Keycloak, check the current password with a password grant, then set the new one through the admin API. The current password is checked again on purpose: a stolen session alone cannot change it.

Example. Ada patches {"name":"Ada L."}. Keycloak gets {"firstName":"Ada L."}. The claims are copied, accountName becomes Ada L., the token is signed again with the same sid, and the new cookie is set. The answer is 204.

Gaps

  • A missing domain blocks sign-in. An ID token naming an organization with no tenancy domain gets 404 from provision, and the person cannot sign in at all (503).
  • Only the first organization is used. A person in two Keycloak organizations is provisioned in the first only.
  • A sleeping screen loses the session. No refresh for 15 minutes means signing in again.
  • No way to revoke one token. A stolen JWT works until exp. sid is not checked anywhere. Logout only deletes the browser’s cookie.
  • Refresh never asks Keycloak. A person disabled in Keycloak stays signed in as long as refreshes keep coming before exp. Only tenancy is asked again.
  • Boot discovery has no timeout. discoverJWKSURL uses http.DefaultClient with the signal context, which has no deadline. A Keycloak that accepts the connection and never answers hangs the start-up instead of failing it.
  • EmailVerified is read and never used. New users are created with emailVerified: false.
