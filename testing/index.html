Integration, Go: testcontainers

registry and tenancy keep their Postgres tests in files tagged //go:build integration.

  • just test tenancy-integration runs go test -tags=integration -count 1 ./....
  • -count 1 turns off Go’s own test cache. moon’s cache: false alone still lets Go replay an old pass, which proves nothing when the real dependency is a running Docker daemon.
  • The command is written as command plus args. Packed into one string, moon dropped the tag, the suite printed [no test files], and the task still exited 0.
  • CI runs go test -tags=integration ./... on every Go module.

Acceptance: across services

just test integration runs backend/acceptance/run-integration-tests.sh.

  1. Generate the ingest keys into .env, so the suite runs without just stack env.
  2. Read RUST_VERSION from .mise.toml.
  3. Write compose.integration-tests.runtime.yml, which include:s only what the suite touches: rust-base, the suite’s Redis and Kafka, telemetry, socket, dashboard, and the test runner.
  4. Remove a stopped leftover ambitwin-socket, never a running one: it may belong to just stack dev.
  5. up --build --exit-code-from integration-tests, under project ambitwin-integration-tests, so it never collides with the dev stack.
  6. down --remove-orphans --volumes, then exit with the tests’ code.

include: rather than several -f flags: each fragment’s relative build.context must resolve from its own folder, and chained -f does not do that reliably.

Agent evals

just test eval models=… judge=… runs backend/agent/evals/run_evals.py --report-only against the local stack.

  1. Read evals/dataset.json: one question per row, with what the answer must contain.
  2. Mint an HS256 eval token, sub evalbot, signed with EVAL_JWT_SECRET from the environment or the repo-root .env. No sign-in is needed; a remote agent needs AUTH_COOKIE instead.
  3. Check once that the agent answers, and stop with a clear error if not.
  4. Ask every row; score it on the expected content.
  5. Rows with llm_judge are also graded by a judge model. They need JUDGE_API_KEY, OPENROUTER_API_KEY or LLM_API_KEY.
  6. A row marked xfail must say why. With --report-only the run reports and exits 0.

just test agent-integration is a separate pytest tests/integration suite.

Coverage

Published from master by cd-coverage.yml, only for services that changed.

LanguageToolOutput
Rustcargo llvm-cov --all-targets, then cargo llvm-cov report --lcovcoverage/coverage-summary.json, coverage/lcov.info
Gogo test -tags=integration -coverpkg=./... -coverprofile=coverage.outcoverage.out, turned into coverage.xml
Pythonpytest --covcoverage.xml
TypeScriptVitest v8 providercoverage/coverage-summary.json, coverage/lcov.info
  1. Each changed service uploads its numbers and its line-level report.
  2. The previous coverage-counts.json and reports/ come from branch coverage-data, so unchanged services keep their last numbers and their last report.
  3. scripts/coverage-summary.py merges them into badge.json and summary.json, and writes reports/<service>.json: per file, the lines and branches covered and the ranges of lines no test runs.
  4. The files are force-pushed as one commit to coverage-data. The push is tried 3 times, 10 s and 20 s apart.
  5. The Test Coverage page of this site fetches summary.json and coverage-counts.json from that branch in the browser, and a service’s reports/<service>.json when its row is clicked.

Example, real numbers from ap-collector. pytest reports app/probes.py with 8 of 145 lines missed: 64, 146, 172-177, 209. reports/ap-collector.json holds the same file as "lines_covered": 137, "lines_total": 145, "uncovered": [[64,64],[146,146],[172,177],[209,209]], and the page shows it first, as 94.5% with links L64, L146, L172–177, L209.
