Plus client, the Vue app everyone uses.

Why Identity needs four services:

  • claims-gateway: answers “who is this?” on every sign-in.
  • tenancy: remembers organizations and memberships.
  • registry: takes a new customer’s signup.
  • provisioner: turns a signup into a running organization.

A signup has no user yet, and a sign-in needs no new customer. They change for different reasons.

Rules of the structure

RuleReason
One database per service, never reach into another’sA model cannot leak through shared tables
Services keep no sessionWho is asking travels with each request
One service, one domainA change stays in one place
High volume goes over a brokerA slow reader never holds back a sensor
Every outbound HTTP call has a timeoutA hang gives no error, so no fallback runs
Shapes that cross a service live in schemas/Two sides cannot drift apart unnoticed
The frontend keeps state in composables and components; a global store only when several screens share itLess hidden state to reason about

A change that breaks one of these is rejected, even with CI green. Rules for how a change is made: Toolchain Overview.
