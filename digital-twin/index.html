digital-twin is a Rust service (Axum, MongoDB, Kafka, Redis) in backend/digital-twin. It implements the Digital Twin architecture. Route /twin/*, checked at the edge.

It owns the spatial model of a building, and it has five jobs:

JobEntry
Register a buildingPOST /register, the worker, the Kafka answer
Read and change buildingsGET and PATCH /building/{id}, lists, counts
Tell other services who owns a buildingGET /domain/{building}
Store where sensors sitGET and PUT /building/{id}/placements
Estimate where phones areKafka wifi-observations

The idea in one minute

Think of an architect’s office that also keeps a live floor plan.

  • A building arrives as a drawing: rooms with a position, a size and a capacity. The office accepts it at once (“received, here is a ticket”) and does the paperwork in the background. The ticket is the handle.
  • The paperwork: file the plan, tell telemetry about it, wait for its “registered” answer, ask dashboard for starting columns. If anything fails, the plan is thrown away and someone is told.
  • The office also knows where each Wi-Fi router is mounted (placements).
  • Every 10 seconds the routers report which phones they heard and how loudly. The office compares the loudness with what each spot on the floor should sound like, and works out where each phone most likely is. Each guess becomes a dot on the 3D plan, and a room count goes to telemetry.
  • Who may look at or change a building is decided by the departments (domains) that own it, with the Cedar rules.

domain/building.rs: the shapes and their checks

pub struct Room {
    pub id: String,
    pub name: String,
    pub capacity: f64,
    pub position: Coordinates,
    pub dimensions: Dimensions,
    #[serde(skip_serializing_if = "Option::is_none")]
    pub color: Option<String>,
}

pub struct Building {
    pub id: String,
    pub name: String,
    pub rooms: Vec<Room>,
    pub domains: Vec<String>,
}

impl PartialEq for Building {
    fn eq(&self, other: &Self) -> bool {
        self.id == other.id
    }
}

A room is a box: position is its centre, dimensions its width, height and depth. A building is its rooms plus the list of domains that own it. Two buildings are “equal” when their ids match, whatever else differs.

Building and Room are not shared shapes: no other Rust service parses them. The cross-language readers (agent, frontend) are kept in line by schemas/fixtures/building.json, checked in tests/building_conformance.rs.

Checking raw input

pub struct PositionInput {
    pub x: Option<f64>,
    pub y: Option<f64>,
    pub z: Option<f64>,
}

impl PositionInput {
    pub fn to_coordinates(&self) -> Result<Coordinates, DomainError> {
        match (self.x, self.y, self.z) {
            (Some(x), Some(y), Some(z)) if x.is_finite() && y.is_finite() && z.is_finite() => {
                Ok(Coordinates { x, y, z })
            }
            _ => Err(DomainError::Validation(
                "position.x, position.y and position.z must be finite numbers".to_string(),
            )),
        }
    }
}

The wire types have Option everywhere, so a missing field does not crash the JSON reader. to_coordinates is the gate: all three present, and is_finite (not NaN, not infinity). Only then do the strict Coordinates exist. DimensionsInput::to_dimensions does the same with one more rule: each must be above 0. validate_capacity wants a finite number of 0 or more.

Registering a building

The HTTP side: add_building

pub async fn add_building(State(state): State<AppState>, claims: GatewayClaims, Json(body): Json<RegisterBuildingRequest>)
    -> Result<(StatusCode, Json<serde_json::Value>), DomainError>
{
    let rooms = body.rooms.into_iter().map(RoomWireInput::into_room).collect::<Result<Vec<_>, _>>()?;

    let building = Building {
        id: Uuid::new_v4().to_string(),
        name: normalize_building_name(body.name.as_deref(), None),
        rooms,
        domains: body.domains,
    };
    let handle = state.provisioning.accept(building, &claims).await?;

    Ok((StatusCode::ACCEPTED, Json(serde_json::json!({ "buildingId": handle }))))
}
  1. Turn every wire room into a checked Room (position, dimensions, capacity, name). The first bad room fails the whole request with 400.
  2. Make the building. The client chooses the room ids, the service chooses the building id (a fresh UUID).
  3. Hand it to accept. Answer 202 Accepted with the handle: “received, not done yet”.

accept: the checks before 202

pub async fn accept(&self, building: Building, claims: &GatewayClaims) -> Result<String, DomainError> {
    if building.domains.is_empty() {
        return Err(DomainError::Validation("A building needs at least one domain".to_string()));
    }
    if !authz::can_edit_every(claims, &building.domains) {
        return Err(DomainError::Forbidden(
            "Requires an editing role in every domain the building is registered to".to_string(),
        ));
    }
    let upload = AcceptedUpload { id: building.id.clone(), building, claims: claims.raw.clone() };
    self.queue.enqueue(&upload).await?;
    Ok(upload.id)
}

Every check runs before the answer, so the service never accepts a building it would refuse later.

RuleError
position has finite x, y, z400
dimensions has finite width, height, depth, all above 0400
capacity present, finite, 0 or more400 capacity must be a non-negative number
domains not empty400 A building needs at least one domain
Editor in every domain403. One foreign domain refuses the whole upload

Then the upload is saved together with the caller’s raw claims header (claims.raw). The worker has no HTTP request to take claims from, and later calls to dashboard need them.

The queue: UploadQueue on MongoDB

A job is a document in pending_uploads. Three queries do all the work:

fn claimable_filter(now: DateTime) -> Document {
    doc! {
        "status": "pending",
        "$or": [
            { "leased_until": null },
            { "leased_until": { "$lte": now } },
        ],
    }
}

fn claim_update(expires_at: DateTime) -> Document {
    doc! {
        "$set": { "leased_until": expires_at },
        "$inc": { "attempts": 1 },
    }
}

fn resolve_filter(id: &str) -> Document {
    doc! { "id": { "$eq": id }, "status": "pending" }
}
  • Claim: find one job that is pending and either never leased or whose lease has run out, and in the same atomic step set a new lease (now + 30 s) and add 1 to attempts. find_one_and_update makes this one operation, so two workers can never take the same job at the same time.
  • Resolve (mark_ready and mark_failed): find the job that is still pending and change its status. It returns the job as it was before, and from that the time since accepted_at. If the job was already resolved, nothing matches and the answer is None: a repeat does nothing.

A lease is like borrowing a library book for 30 seconds. If the borrower (the worker) crashes, the book comes back by itself when the time runs out and someone else can take it. That is why a crash in the middle of provisioning loses nothing.

Indexes on pending_uploads:

// unique id; (status, leased_until) for claims; finished_at with expire_after(1 h)
col.update_many(
    doc! { "status": { "$in": ["ready", "failed"] }, "finished_at": null },
    doc! { "$set": { "finished_at": DateTime::now() } },
).await?;

The last statement runs at every start. A TTL index never removes a record that lacks its field, so uploads finished before expiry existed would otherwise stay forever. This gives them a finished_at now.

The worker

const LEASE: Duration = Duration::from_secs(30);
const IDLE_POLL: Duration = Duration::from_millis(50);

pub fn spawn(provisioning: Arc<Provisioning>) -> tokio::task::JoinHandle<()> {
    tokio::spawn(async move {
        loop {
            match provisioning.provision_next(LEASE).await {
                Ok(true) => {}
                Ok(false) => tokio::time::sleep(IDLE_POLL).await,
                Err(e) => {
                    log::error!("provisioning loop stalled: {e:?}");
                    tokio::time::sleep(IDLE_POLL).await;
                }
            }
        }
    })
}

A loop that never ends:

  • It did a job: go straight back for the next one.
  • No job: sleep 50 ms.
  • An error (for example MongoDB is down): log it, sleep 50 ms, try again.

provision_next and provision

pub async fn provision_next(&self, lease: Duration) -> Result<bool, DomainError> {
    let Some(upload) = self.queue.claim(lease).await? else {
        return Ok(false);
    };

    if let Err(e) = self.provision(&upload).await {
        log::error!("provisioning {} failed: {e:?}", upload.id);
        self.fail(&upload.id, &format!("{e:?}")).await?;
    }
    Ok(true)
}

async fn provision(&self, upload: &AcceptedUpload) -> Result<(), DomainError> {
    self.buildings.upsert(&upload.building).await?;
    self.events.publish_building_registration_request(&upload.building).await?;
    self.downstream.init_preferences(&upload.building.id, &upload.claims).await;
    Ok(())
}
  1. Claim a job. None: return false.
  2. Store the twin (an upsert, so doing it twice converges on one twin).
  3. Publish building-registration-requested to Kafka. The key is the building id.
  4. Ask dashboard for starting columns. This one returns nothing: a failure is only logged.
  5. If step 2 or 3 failed, the upload is failed on the spot (see fail below).

The worker does not mark the job done. The job stays pending with its lease running until telemetry answers.

Example. telemetry is down for 2 minutes. The job is claimed at 0 s, 30 s, 60 s, 90 s, 120 s: 5 attempts, 5 identical requests on Kafka. When telemetry comes back it registers the building 5 times (each an upsert) and answers 5 times. The first ready resolves the job. The other 4 match nothing.

  • attempts grows, but nothing reads it: there is no retry limit.

adapters/driving/kafka_consumer.rs, group building-registrations-completed.

Read from the oldest unread message, and commit by hand, only after the answer is resolved.

async fn handle_payload(payload: &[u8], provisioning: &Provisioning) -> Disposition {
    let event: RegistrationCompleted = match serde_json::from_slice(payload) {
        Ok(e) => e,
        Err(e) => { log::error!("malformed registration-completed event: {e:?}"); return Disposition::Settled; }
    };

    let error = event.failure();
    match provisioning.resolve(&event.building_id, error.as_deref()).await {
        Ok(Some(elapsed)) => { /* record the duration, ready or failed */ Disposition::Settled }
        Ok(None) => Disposition::Settled,
        Err(e @ DomainError::Internal(_)) => { /* log */ Disposition::Retry }
        Err(e) => { /* log */ Disposition::Settled }
    }
}
Result of resolveWhat the consumer does
Malformed messageLog it and commit. Reading it again gives the same answer
Ok(Some(time))The job changed. Record the time since accept, commit
Ok(None)Nothing changed: a repeat. Commit
Internal error (the store failed)Retry: stop, reconnect after 5 s, read the same message again
Any other errorLog it and commit
if handle_payload(payload, provisioning).await == Disposition::Retry {
    anyhow::bail!("answer at offset {} unresolved, rereading", message.offset());
}

Retry ends the loop with an error without committing. The outer spawn loop waits 5 s and starts again. Reconnecting rewinds to the last commit, so the unresolved answer is read again.

resolve and fail

pub async fn resolve(&self, id: &str, error: Option<&str>) -> Result<Option<Duration>, DomainError> {
    match error {
        None => Ok(self.queue.mark_ready(id).await?),
        Some(e) => self.fail(id, e).await,
    }
}

// A failed upload must not leave an orphaned twin behind -- whether provisioning
// failed before telemetry ever heard about it, or telemetry rejected it later.
// Notify before deleting: notification resolves the building's domains by
// calling back into digital-twin, so the twin must still exist when it does.
async fn fail(&self, id: &str, error: &str) -> Result<Option<Duration>, DomainError> {
    let Some(elapsed) = self.queue.mark_failed(id, error).await? else {
        // Already failed means a retry: notify went out, only the delete may be outstanding.
        if self.queue.status(id).await? == Some(UploadStatus::Failed) {
            self.buildings.delete(id).await?;
        } else {
            log::warn!("registration of {id} failed after the upload was resolved: {error}");
        }
        return Ok(None);
    };
    self.downstream.notify_provisioning_failed(id, error).await;
    self.buildings.delete(id).await?;
    Ok(Some(elapsed))
}
  • Ready: mark the job ready (only if it is still pending).
  • Failed: mark it failed, send the alert first, then delete the building. The order matters: notification finds the building’s domains by calling back GET /domain/{building}. After the delete, that call would find nothing, and the alert would reach nobody.
  • A repeat of failed: mark_failed changes nothing (None). If the job is already failed, the delete may have failed last time, so only the delete runs again. No second alert.
  • A failed for a job that is ready: logged, nothing deleted. So a resync that telemetry rejects can never delete a live twin.

Polling the status and resync

GET /building/{id}/status reads pending_uploads and answers {"status": "pending" | "ready" | "failed"}. 404 No upload with handle when the job is unknown, or more than 1 hour after it finished. It needs only a signed-in caller.

POST /building/{id}/sync is resync: read the stored building, check the caller edits one of its domains, and publish the same registration request the worker would. Use it when telemetry lost a registration. It writes nothing here.

normalize: repairing on read

async fn normalize(&self, mut building: Building) -> Result<Building, DomainError> {
    let mut changed = false;
    let normalized = normalize_building_name(Some(&building.name), Some(&building.id));
    if normalized != building.name { building.name = normalized; changed = true; }
    for room in &mut building.rooms {
        let normalized = normalize_room_name(Some(&room.name), &room.id);
        if normalized != room.name { room.name = normalized; changed = true; }
    }
    if changed { self.store.upsert(&building).await?; }
    Ok(building)
}

A stored blank name is replaced by the id. If anything changed, the building is written back, so the repair happens once. Reading can write.

Changing a building

pub async fn update(&self, id: &str, patch: BuildingPatch, claims: &GatewayClaims) -> Result<Building, DomainError> {
    let mut building = self.get_building_by_id_for_edit(id, claims).await?;

}
  1. Load the building and check the caller edits one of its current domains.
  2. Apply name and domains if present.

  • Rooms cannot change: the patch has no room field. The room set is write-once.

Estimating phones from Wi-Fi

This is the most original part of the service. In plain words: the louder a router hears a phone, the closer the phone is. With three or more routers, there is usually one spot on the floor that explains all the loudness numbers at once.

Geometry::of: cutting the building into cells

  1. Floors. Take each room’s bottom, y − height / 2. Sort the bottoms. Bottoms within 0.5 m of each other are one floor.
  2. Cells. On each floor, cover the rooms’ outline with 0.5 m squares, and keep only the cells that fall inside a room.
  3. Routers. Each placement goes on the floor its y falls on. Every placed sensor is used; only routers ever appear in a tick.
  4. Expected signal. For every cell and every router on its floor, work out how loud that router should hear a phone standing there.
pub fn expected_signal(metres: f64, walls: usize) -> f64 {
    SIGNAL_AT_1M_DBM                                    // -40
        - 10.0 * PATH_LOSS_EXPONENT * metres.max(1.0).log10()   // 22 * log10(distance)
        - WALL_LOSS_DB * walls as f64                   // 5 per wall
}

The rule: −40 dBm at 1 m, 22 × log10(distance) lost with distance, and 5 dB lost per wall. The distance is never taken below 1 m. This is the same radio rule ap-simulator uses.

For each room outline, find where the straight line from the cell to the router crosses its edges (an old line-clipping method called Liang-Barsky). Sort all crossings along the line. Crossings closer than 0.3 m to each other count as one wall: rooms drawn edge to edge rarely share a coordinate exactly, so two outlines meeting at a wall would otherwise count twice.

Scoring the cells: posterior

For every cell on the floor:

  1. Misfit = the sum of (heard − expected)², divided by 2 × 4.5². The 4.5 is the noise of the signal (the simulator’s 4 dB shadowing and 2 dB fading, combined).
  2. With a prior (where the phone was last time): drop cells farther than its reach, and add distance² / (2 × prior variance), a pull toward the old place.
  3. The best (lowest) cost is low. Each cell’s weight is e^(low − cost). The best cell weighs 1.
  4. The position is the weighted mean of the cell centres. The spread comes from the weighted distances, at least 0.5 m.

For a burst with no prior, pick the floor of the loudest router (a floor slab costs about 18 dB, so the loudest one is on the right floor). Then at least 3 routers placed on that floor must have heard it: two circles cross at two points, and the third router picks one. Fewer than 3: no fix.

Following phones: Tracks::step

pub const MAX_SPEED_M_S: f64 = 2.0;
const DRIFT_M_S: f64 = 0.5;
pub const FORGET_AFTER_TICKS: u64 = 3;
const RING_TOLERANCE_DB: f64 = 9.0;

A tick has two kinds of rows: connected (phones joined to a router, each with a stable token) and bursts (phones only passing, heard by several routers). step does this:

  1. Group the connected rows by token: each phone’s own signals.
  2. For each burst:
    • its token is a connected phone: add its signals to that phone;
    • otherwise compute a fix, then find the phones that fit: one of the phone’s own signals is within 9 dB of what that router should hear at the fix, and the phone could have walked there;
    • exactly one fits: add the burst to that phone;
    • none fits: someone passing, a dot with connected: false;
    • two or more fit: drop it. Guessing would give one phone the other’s path.
  3. Update each phone’s track with posterior, using its last place as the prior. If nothing is within reach, start again from the signals alone.
  4. Forget a token unseen for 3 ticks. One failed poll must not end a track.
  5. Each track becomes a dot: floor, nearest room, x, y = floor height, z, radius = the spread, connected: true.
fn prior(&self, now_ms: u64) -> Prior {
    let seconds = now_ms.saturating_sub(self.at_ms) as f64 / 1000.0;
    Prior {
        x: self.x,
        z: self.z,
        variance: self.variance + (DRIFT_M_S * seconds).powi(2),
        reach: MAX_SPEED_M_S * seconds + 2.0 * self.variance.sqrt(),
    }
}

The older a track, the less it is trusted: its variance grows with time, and its reach (how far the phone may have walked) grows at 2 m/s, which is faster than anybody walks.

Gaps

  • PATCH can move a building into any domain. It checks the editing role only in the building’s current domains. The new domains list is not checked, and may even be empty. POST /register checks every domain.
  • PATCH saves before telemetry answers. When the limit sync fails, the caller gets 500 but the new name and domains are already stored.
  • No retry limit. A job telemetry never answers is republished every 30 s for ever. attempts is counted but never read.
  • init_preferences ignores the answer code. A 4xx or 5xx from dashboard looks like success, and the building gets no live feed until someone saves its columns.
  • Status and ownership lookup need only a signed-in caller. Any user can learn a building’s domains, or an upload’s status, from its id or name.
  • The rate limit lives in memory. Two copies of the service each allow 300 per minute.
  • Placements outlive their building. A failed upload deletes the building, never its placements document.
  • A blank building name at registration becomes Building, not the id. The id is only used later, when normalize repairs a stored blank name.
