Go module at backend/libs/auth-middleware. It turns a request into an authcontracts.StandardClaims before any handler runs, in one of two ways.

Entry pointChecks a signature?Used byReads
RequireAuthentication(jwks, issuer)Yesclaims-gateway: /me, /profile, /refresh, /verifyAuthorization: Bearer … or cookie authentication_token
RequireMeshClaims()Notenancy: all routes outside /internal/*Header x-gateway-claims
FromContext(ctx)—Handlers in both servicesThe claims either entry point stored

Dependencies: golang-jwt/jwt/v5, MicahParks/keyfunc/v3, and auth-contracts.

Why two entry points

  • claims-gateway makes the token, and the edge asks it whether a token is good (/verify). It cannot hand that check to anyone else, so it checks the signature itself.
  • Every other service sits behind the edge. The edge already checked the token once and wrote its claims into x-gateway-claims. Checking again would repeat the work with the same key.

registry and provisioner use neither: their only routes are /internal/*, checked by auth-contracts’ RequireSignature, and provisioner has no routes at all.

1. RequireAuthentication

Where it runs

In the cluster, Istio’s RequestAuthentication does steps 2 to 9 itself, with the public keys from /gateway/.well-known/jwks.json, and writes the header with outputPayloadToHeader: x-gateway-claims.

claims-gateway builds its jwks from its own key at start-up (keyfunc.NewJWKSetJSON(sign.JWKS()) in cmd/gateway/main.go): no network call to check a token.

Step by step

  1. Find the token. extractToken looks at Authorization first: a value starting with Bearer wins. Otherwise it reads the authentication_token cookie. Neither: 401 unauthenticated.
  2. Check the token. jwt.ParseWithClaims with:
    • jwks.Keyfunc: picks the public key named by the token’s kid;
    • WithValidMethods(["RS256"]): any other alg, like none or HS256, fails;
    • WithIssuer(issuer): a token from another signer fails;
    • the library also refuses a token whose exp is in the past. Any failure: 401 invalid token.
  3. Read the claims with decodeClaims (below). Failure: 401 invalid token claims.
  4. Store the claims in the request context under a private key type, and call the next handler.

decodeClaims

The JWT library gives a loose map (jwt.MapClaims). decodeClaims copies it into StandardClaims:

  1. sub must be a non-empty string, or error claims: sub is required. Every access decision keys on sub; an empty one is a nameless caller with a valid signature.
  2. accountName and sid: copied when they are strings, else empty.
  3. memberships missing or not a list: no error, empty list. A new account has no domain yet.
  4. Each entry that is not an object is skipped. From each object: domain, role, externalId when strings.

Example. Claims {"sub":"acc-1","memberships":["acme",{"domain":"unibo","role":"standard_customer"}]}:

StepResult
1Sub = acc-1
2AccountName = "", SID = ""
4"acme" is not an object: skipped. Memberships = [{unibo, standard_customer}]

No signature check here: the header is trusted because the edge writes it after checking the token. On a gated route the edge sets the header from the checked token; on /agent/*, which is not gated, both edges remove any x-gateway-claims the client sent.

3. FromContext

claims, ok := authmiddleware.FromContext(r.Context())
  • Both entry points store the same type under the same key, so a handler does not care which one ran.
  • The key is the private empty type contextKey struct{}. No other package can make one, so no other code can overwrite or fake the stored claims.
  • ok is false only when no middleware of this package ran on the route.

Gaps

  • Only one base64 alphabet. RequireMeshClaims uses StdEncoding: + / and = padding. The Rust crate claims-schema accepts four alphabets, including URL-safe without padding, because “the edge may emit” them. If Istio writes URL-safe or unpadded base64, tenancy answers 401 where every Rust service passes. The local edge is safe: verifyHandler writes standard base64.
  • A token without exp never expires. jwt/v5 checks exp only when present. Harmless while claims-gateway is the only signer and always sets it.
