Rust crate at schemas/twin-schema. It holds every shape digital-twin exchanges with another service, and the topic and channel names they travel on.

Depends only on serde and serde_json. Tests also use jsonschema.

Reading rooms leniently

usable_rooms reads rooms as a list of plain JSON values and keeps what it can:

Example. [{"name":"ghost"}, {"id":""}, "r0", {"id":"r1"}] gives one room: r1, named r1.

Why: a room with no id cannot be stored or found again. Failing the whole building for one such room would refuse a building for a room nobody can use anyway.

Reading the answer

failure() turns the answer into “done” or a reason:

Example. {"buildingId":"b1","status":"exploded"} reads as a failure with reason exploded.

Why status is text and not an enum: an unknown value would then fail to parse. A message that fails to parse is logged and skipped, so the upload would stay pending for ever. As text, anything that is not ready fails the upload, with a reason.

Who decides failed

telemetry answers failed only when the request itself is wrong: no name, a NUL character, a maxTemperature that is not a number. A database error in telemetry is not answered: the message is read again later. Answering failed would make digital-twin delete the building.

2. The Wi-Fi tick

Shape

{"buildingId":"bldg-3f2b4c5d","tick":1761300000000,
 "answered":["e6f7…","f708…","0819…"],
 "connected":[{"token":"7f3c9a01b2d4e6f8","router":"e6f7…","signal":-61},
              {"token":"c2d4e6f8091a2b3c","router":"f708…","signal":-70},
              {"token":"c2d4e6f8091a2b3c","router":"0819…","signal":-72}],
 "bursts":[{"token":"a91e0c3d5f7b2846","started":1761299998412,
            "heard":{"e6f7…":-58,"f708…":-71,"0819…":-80}}]}

Router ids are UUIDs, cut here.

FieldMeaning
buildingIdThe building whose key signed the tick
tickWhen the collector took the snapshot, ms since 1970
answeredRouters that replied. A router missing here failed: its phones are unknown, not gone
connectedOne row per router listing a phone. One token on two rows is one phone heard twice
burstsScans heard: token, start time in ms, and each router’s loudest signal. Always present, empty when scanning is off
devicesPerPersonOptional. Phones per person for this site; without it, no people estimate

No MAC address and no coordinates ever: tokens are random per tick, positions belong to digital-twin.

The rules, in two places

Checked byRule
serde, deny_unknown_fieldsNo extra field anywhere. A mac beside a token fails
problems()buildingId not empty
problems()Each router in answered once, not empty
problems()devicesPerPerson, when present, finite and above 0
problems()At most 2000 connected rows (MAX_CONNECTED), 2000 bursts (MAX_BURSTS)
problems()Token: exactly 16 characters, 0–9 and a–f
problems()Signal from −127 (MIN_SIGNAL) to 0 dBm, router not empty
problems()A burst heard by 1 to 6 routers (MAX_HEARD)

problems() returns one message per broken rule, empty when the tick is sound. The limits keep a tick of UUID router ids under telemetry’s 1 MiB body limit.

Why no extra fields: telemetry forwards the received bytes to Kafka. An unchecked field would travel with them.

A tick end to end

digital-twin runs problems() again: it does not take the broker’s word for it.

Example, step 4. Phone c2d4… is on two routers at −70 and −72 dBm. It counts once, in the room of the −70 router. Phone 7f3c… counts in its router’s room. Result: 2 phones, in up to 2 rooms.

4. Room counts for telemetry

{"buildingId":"bldg-3f2b4c5d","tick":1761300000000,"rooms":{"room-lobby":3,"room-office":0}}
RuleWhy
One message per accepted tick, only when at least one router answeredNo answer would record an empty building that is not empty
Every room on a floor with a placed router, zeros includeddigital-twin can place no one on a floor with no router
Connected dots onlyA passing dot is placed too rarely to count
Counts only, deny_unknown_fieldsNo position can ride along
Topic keyed by buildingId, kept 1 h, created by digital-twinAn hour of history survives a telemetry restart

telemetry stores each room as an estimatedOccupancy reading at the tick’s time (kernel/occupancy.rs). It never touches totalDeviceCount, which is telemetry’s own count.

Example. The message above becomes two readings at 1761300000000: room-lobby 3, room-office 0.

What stays out of this crate

Building, Room, Coordinates, Dimensions stay in digital-twin/src/domain/. No other Rust service parses them: the ownership lookup GET /domain/{building} answers a plain list of domain names.

The full building is read by agent (Python) and the frontend (TypeScript). A fixture holds them in line:

Rustdigital-twin/tests/building_conformance.rs: parses schemas/fixtures/building.json into the real Building, writes it back, compares
